# ADR-0022: 起動時に直近のノートを開き、未選択ではエディタを出さない

- 日付: 2026-08-19
- ステータス: 採用
- 関連: ADR-0002（読み込み専用モードの廃止 = 「打てるのに保存されない」経路）、
  ADR-0017（undo の履歴は `replace_content` で畳む）、
  `docs/review-2026-08-17-public-release.md` の §3-1（この ADR はその解消方針）

## 文脈

<!-- どんな問題・制約の中で決めたか。評価軸の優先度を先に書く（総合点方式の罠を避ける） -->

公開可否レビュー §3-1。**ウェルカム画面は「打てるのに保存されない」**（ADR-0002 が廃止した経路と同型）。

ノート未選択でもエディタは編集を受け付けるが（`src/main.rs` の `editor_pane`）、
`mark_edited` は `selected` が無いと dirty を立てず、`begin_save` も未選択なら即抜ける。
打った本文はノートを開いた瞬間 `replace_content` で無警告に消える。

`selected` が `None` になる経路はコード全体で **2 つだけ**だった:

| 経路 | 場所 | そのときの本文 |
|---|---|---|
| 起動 / vault 読み込み | `boot` と `adopt_vault` | `WELCOME` の案内文がエディタの中身として入る |
| 削除 | `delete_note` | 空文字。繰り上げの計算を避けるため意図的に選択を外していた |

評価軸の優先度:

1. **打った本文を失わないこと**
2. 起動してすぐ書けること
3. **状態を増やさないこと**（BSSN。ガードを足すより状態を消すほうが小さい）

## 決定

<!-- 何を選んだか1〜3行 -->

**2 本柱。結果として「未選択 ⟺ ノートが 0 件」という不変条件が立つ。**

### 柱 1: 読み込み直後、ノートがあれば一覧の先頭を開く

`vault::sort_notes` が `modified` 降順で固定しているので、**先頭 = 直近に更新されたノート**。
vault は作成時刻を持たないため基準は更新時刻だが、作った直後のノートは mtime = 作成時刻なので
「最も新しく作られたノート」とはほぼ一致する。`boot` と `adopt_vault`（セットアップ経由）の
両方から同じ `open_newest` を通す。

**ディスクへの書き込みは増えない。** 選択がやるのは `replace_content` だけで、`begin_save` は
`contents == raw` で抜ける。Done の定義「何も編集せずノートを切り替えたらディスクに書かない」は無傷。

### 柱 2: `selected` が `None` のときはエディタを描かない

`text_editor` の代わりに空状態の面（`empty_pane`）を出し、`Cmd+N` を案内する。
**打とうとする経路そのものが無くなる**ので、ガードが要らない。

### 不変条件

> **`selected.is_none()` ⟺ `notes.is_empty()`。エディタが画面にあるなら、書いた先のノートが必ずある。**

これを保つため、削除後も選択を維持する: `min(index, len - 1)`（**消した位置に居続ける**。
末尾を消したときだけ 1 つ前）。最後の 1 件を消したときだけ未選択に戻り、空状態の面が出る。

## 却下した代替案

<!-- 何を・なぜ見送ったか。「なぜこれでないのか」が将来いちばん効く記録 -->

- **未選択のエディタを読み取り専用にする**（レビューの提案）。実装 1 行で失われる入力もゼロ。
  却下は優先度 3 で、**「打てない編集領域」という説明の要る状態が増える**ため。
  「書き始めようとしたのに打てない」は、原因が画面から読み取れない
- **未選択で打鍵したら暗黙に新規ノートを作る。** 書き始めがそのままメモになるのは魅力だが、
  `Cmd+N` の「押しただけで空ファイルが残る」問題（implementation-notes の未決事項）を広げる。
  誤打鍵のたびにノートが増える
- **起動時に空ノートを 1 件作って必ず選択させる。** 同じ穴に加えて、起動のたびにゴミが増える
- **最後に開いていたノートを覚えて復元する。** config に状態が増え、覚えたノートが消えていた
  ときの分岐も要る。**直近に更新されたノートはたいてい最後に触ったノート**なので、
  覚えなくても同じ結果になる。必要になったら足せる
- **削除後は一覧の先頭へ戻す。** 起動時と規則が揃うが、`Cmd+Delete` を連打すると毎回
  視点が一覧の先頭へ飛ぶ。消した文脈に居続けるほうが操作として自然

## 帰結

<!-- この決定で背負うトレードオフ -->

- **起動直後の誤打鍵が「直近のノートへの追記」になる。** 以前はその打鍵が失われていたので、
  失うより良い。どのノートに書いているかは一覧のハイライトとタイトルで分かる
- 起動時に先頭ノートの本文を 1 回クローンする（`open_note` と同じ経路）。`load_ms` の計測範囲外で、
  40 万字のノートでも `view()` 構築は 0.47ms 実測なので体感には出ない
- **空状態の面が出るのは vault が 0 件のときだけ** — 初回セットアップ直後と、全部削除した後
- `WELCOME` は「一覧から選べ」ではなく「最初のノートを作れ」の文言になる（`EMPTY_VAULT`）
- 削除の回帰テストが `selected == None` を前提にしていたので更新した

## 学び

**安全装置を足す前に、その状態が本当に要るかを問う。** レビューの提案（読み取り専用にする）は
正しいガードだった。しかしガードが要るのは守るべき状態があるからで、**状態のほうを消せば
守るものが減る**。「未選択でエディタが出ている」状態を消したら、ガードも説明も一緒に消えた。
