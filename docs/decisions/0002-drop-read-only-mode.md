# ADR-0002: 読み込み専用モードを廃止する

- 日付: 2026-08-09
- ステータス: 採用

## 文脈

<!-- どんな問題・制約の中で決めたか。評価軸の優先度を先に書く（総合点方式の罠を避ける） -->

前身（gpui 版）には「`VAULT` を指定して開いた vault は読み込み専用が既定で、書き込みは
`ALLOW_WRITE=1` の明示オプトイン」という仕組みがあった。借り物のデータ（別プロジェクトの wiki 等）を
誤って壊さないための安全装置で、README にも「事故側に倒れないようにする」と書いていた。

移植の検証中に実機で触って、**この安全装置が最悪の事故を作っていた**ことが分かった。
読み込み専用でもエディタは普通に打てる。しかし保存だけされない。つまり書いた本文は
ディスクにもメモリにも残らず消える。メモアプリで唯一許されない事故がこれで、
守るつもりだったデータ保護のために、目の前で書いている本文を捨てていた。

評価軸の優先度:

1. **書いた本文を失わないこと**。他のどの性質より優先する
2. 挙動が予測できること（できることとできないことが見た目で分かる）
3. 借り物データを壊さないこと

## 決定

<!-- 何を選んだか1〜3行 -->

**読み込み専用モードを廃止する。** `allow_write` フィールド・`ALLOW_WRITE` 環境変数・
「読み込み専用のため保存できません」エラー・`save_now()` の分岐をすべて削除した。
`VAULT=` で vault を切り替える機能だけを残し、**開いた vault は常に編集・保存できる**。

## 却下した代替案

<!-- 何を・なぜ見送ったか。「なぜこれでないのか」が将来いちばん効く記録 -->

- **読み込み専用時は編集操作をブロックする**（`Action::Edit` を無視する）。事故は防げるし閲覧用途も
  残る。実装も数行で済むので有力だった。却下したのは、**そもそも「書けない状態」がメモアプリに要るのか**
  という問いに答えられなかったため。閲覧だけなら他のツールで足りる
- **読み込み専用時は閲覧専用ビューに切り替える**。誤解の余地はゼロになるが、編集ビューと閲覧ビューの
  2系統を維持することになる。BSSN に反する
- **現状維持**。論外。書いた本文が消える

## 帰結

<!-- この決定で背負うトレードオフ。非標準技術なら innovation token の消費として明記 -->

- **借り物 vault を開くと編集・保存できてしまう。** 壊したくないなら開かない、という運用に委ねる。
  安全装置をコードから外して人間の判断に戻した形なので、これはトレードオフとして自覚しておく
- 概念が1つ減った。環境変数・分岐・エラー文言・ステータス表示が消え、
  「開いたものは書ける」という一言で説明できるようになった
- **前身にはこの欠陥が残ったまま凍結してある。** あちらを再開したり
  公開したりするなら、まずここを直すこと

## 学び

安全装置は、**それが作動したときに何が起きるか**まで設計しないと、守るつもりのものを壊す。
「保存を止める」までは設計していたが、「止めたあと、ユーザーが書いた文字はどこへ行くのか」を
設計していなかった。今回は引き算で経路そのものを消したが、機能を足して安全にしようとするときは
必ずこの問いを通すこと。
