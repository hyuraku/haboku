# ADR-0019: Markdown プレビューは `Cmd+Shift+V` の置き換えトグルにする

- 日付: 2026-08-15
- ステータス: 採用

## 文脈

<!-- どんな問題・制約の中で決めたか。評価軸の優先度を先に書く（総合点方式の罠を避ける） -->

VSCode / Zed にある「Markdown をレンダリングして読む」機能が欲しい、という要求。
書く体験は変えない（生の Markdown を打つ）ことは要求の時点で確認済みで、
spec の非目標「WYSIWYG / プレビュー分割」と衝突するのは**読み方**の部分だけだった。
非目標の本質は「編集を WYSIWYG にしない」であって「読むための表示を持たない」ではない、
と整理し、非目標を「WYSIWYG 編集・プレビュー分割ペイン」に絞り直した。

評価軸の優先度:

1. **書く体験を変えない**。エディタは常に生テキストのまま
2. 押した結果が予測できること（ADR-0004 と同じ軸）
3. BSSN。今の要求「コマンドを押したらプレビューが見れる」だけを解く

## 決定

<!-- 何を選んだか1〜3行 -->

**`Cmd+Shift+V` でエディタ領域を読み取り専用プレビューに置き換える。再押下か Escape で戻る。**
描画は iced 標準の `markdown` ウィジェット（feature 1 つ、増える依存は pulldown-cmark のみ）。
プレビュー状態はノート切替をまたいで維持し、「閲覧モード」として読み歩ける。

設計の要点:

- **このトグルは成立する。** ADR-0004 で `Cmd+P` のトグルを諦めたのは、消費できない
  イベントがフォーカス中の入力欄へ文字として混入するため。プレビュー中はエディタ自体が
  view に無いので、再押下の漏れ先が無い。開く方向も `editor_key_binding` が
  ⌘ 付き Insert を捨てる（ADR-0010）ので混入しない
- **パースを `view()` に置かない。** パース済み `markdown::Content` を App が持ち、
  作り直すのはトグルで開いた瞬間と `replace_content`（本文差し替えの合流点）だけ。
  プレビュー中は編集が起こらないので、この 2 点で表示と本文はズレない
- **書体は本文もコードも `BIZ UDGothic` を名指しする。** コード既定の `Font::MONOSPACE` は
  cosmic-text が漢字に GB18030 Bitmap を選んで**漢字だけ消える**（ADR-0003 / ADR-0013 の罠）。
  本文を `Font::DEFAULT` のままにした版では、**イタリック span（`*斜体*`）の漢字が
  豆腐グリフに化ける**のを実機で観測した。CJK に italic face は無く、cosmic-text は
  イタリック要求のフォールバックで壊れたフォントを選ぶ。名指しのファミリなら
  斜体にはならない（立体のまま）が、文字は 1 つも消えない — このトレードオフを取る
- プレビュー中の文字キー・`Cmd+Z` は本文に効かない（「見えていない本文を書き換えない」。
  ADR-0016 / ADR-0017 と同じ規律）
- リンクは `/usr/bin/open` で既定ブラウザへ（macOS 専用アプリなので依存を増やさない）
- **画像は描画しない。** ウィジェットは URL を返すだけで読み込みは自前実装になるが、
  実データでの使用が 0 件（2026-08-15 時点、13 ノート走査）

## 却下した代替案

<!-- 何を・なぜ見送ったか。「なぜこれでないのか」が将来いちばん効く記録 -->

- **分割ペイン（Zed 風のライブプレビュー）**。既に 3 ペインで横幅が苦しく、幅調整・
  スクロール同期という付随論点が湧く。置き換えトグルは分割の真部分集合で、
  足りなければ後から育てられる（逆は戻れない）
- **打鍵で自動的に編集へ戻る**。誤爆した打鍵が本文へ入る経路になる。
  プレビュー中の文字キーは無視し、戻る操作は明示（再押下 / Escape）に限る
- **ノート切替でプレビューを解除する**。リセット条件のコードが増えるだけで、
  「読み歩き中に勝手に編集画面へ落ちる」驚きのほうが大きい。一瞬確認したい用途は
  Escape 一発で足りる
- **`[[wiki リンク]]` の解決・画像表示**。実データ 0 件。YAGNI

## 帰結

<!-- この決定で背負うトレードオフ。非標準技術なら innovation token の消費として明記 -->

- iced の feature が 1 つ増えた（`markdown`）。innovation token の消費ではない
  （iced 自身の同梱機能で、新しい技術選定を伴わない）
- プレビューの見た目は iced 標準ウィジェットの割り付けに従う。余白・見出しサイズを
  細かく変えたくなったら `Viewer` トレイトの自前実装が要る（今は要らない）
- 「トグル型ショートカットは設計段階で避ける」（ADR-0004）に例外が 1 つできた。
  例外の条件は**押した瞬間に漏れ先の入力部品が画面から消えていること**。
  この条件を満たさない限り、今後もトグルは作らない

## 学び

ADR-0004 の「トグル不成立」は普遍の制約ではなく、**フォーカス中の入力欄が存在するとき**の
制約だった。制約を記録するときは、結論だけでなく成立条件まで書いておくと、
あとから例外を安全に見分けられる。
