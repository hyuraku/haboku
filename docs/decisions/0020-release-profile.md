# ADR-0020: 配布バイナリは LTO + strip で削り、`panic = "abort"` は入れない

- 日付: 2026-08-16
- ステータス: 採用

## 文脈

「機能を減らさずに容量を減らす」ためのリファクタリングで、`Cargo.toml` に
`[profile.release]` が 1 つも無いことが分かった。既定のまま（`lto = false` /
`codegen-units = 16` / シンボル未 strip）でビルドした `target/release/haboku` は
**15,088,864 バイト（14.4 MiB）**。iced → wgpu → syntect と依存ツリーが深いので、
crate をまたいだ dead code 削除が効いていない状態だった。

評価軸の優先度:

1. **挙動を変えない**。サイズのために失敗時の振る舞いを変えない
2. **今の性能要件を落とさない**（起動 50ms / `view()` 構築 1ms 未満）
3. サイズ

## 決定

**`lto = "fat"` / `codegen-units = 1` / `strip = "symbols"` の 3 つだけを入れる。**

```toml
[profile.release]
lto = "fat"
codegen-units = 1
strip = "symbols"
```

実測: **15,088,864 → 9,650,656 バイト（−36.0%）**。ビルド時間は 1m43s に伸びた。

3 つとも生成コードの意味を変えない設定で、実行時の挙動に差が出ない。
`opt-level` は `3` のまま触らない（`"s"` / `"z"` は上の評価軸 2 と直接ぶつかる）。

## 却下した代替案

- **`panic = "abort"`**。数百 KB は削れるが、ADR-0014 で保存の `sync_all` を
  `spawn_blocking` へ出したため、**保存タスクのパニックが `JoinError` として
  返ってくる経路が保存エラー処理そのもの**になっている。abort にすると
  「保存に失敗したのでエディタに本文を残す」が「プロセスが即死して本文が消える」に
  変わる。これは容量のために機能を落とすことなので取らない
- **iced の `highlighter` feature を外す**。`two-face` の syntax dump 920KB + themes 46KB と
  syntect / fancy-regex が落ち、1〜2MB 削れる。エディタ側は ADR-0009 で
  自前の `highlight.rs` に置き換え済みなので無影響。**しかし `Cmd+Shift+V` の
  プレビュー（ADR-0019）でコードブロックの配色が単色になる**
  （`iced_widget/src/markdown.rs` が同じ feature でガードされている）。
  「機能を減らさずに」という前提に反するので見送り。**サイズ 1〜2MB と
  プレビューのコードブロック配色の等価交換**として、必要になったら再考する
- **`opt-level = "s"` / `"z"`**。`view()` 構築 1ms 未満と起動 50ms が実測で
  守られている状態を、測りもせずに崩す取引になる

## 帰結

- クリーンな release ビルドが 1m43s かかるようになった（`lto = "fat"` +
  `codegen-units = 1` の代償）。デバッグビルドは無影響
- `strip = "symbols"` で release のバックトレースからシンボル名が消える。
  端末起動時の `eprintln!` による診断（`vault:` 行）は残るので、
  利用者から状況を聞き取る経路は失っていない
- サイズを削る余地としていちばん大きいのは `highlighter` feature（1〜2MB）だが、
  それはプレビューの機能と交換になる、と記録しておく

## 学び

サイズ削減の設定は「無害なもの」と「失敗時の振る舞いを変えるもの」に割れる。
`panic = "abort"` は前者の顔をして後者にいる。**削る前に、失敗したときに何が
起きるかを先に見る**（CLAUDE.md の「安全装置は、失敗したときに何が起きるかまで設計する」）。
