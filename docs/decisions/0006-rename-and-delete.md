# ADR-0006: リネームはファイル名だけを変え、削除は確認なしで `.trash` へ退避する

- 日付: 2026-08-09
- ステータス: 採用（**一部を ADR-0007 が取り消し**）

> **追記（2026-08-10）**: 下の却下案「削除の前に保存する」は **ADR-0007 で取り消した**。
> 却下理由の「保存に失敗したときに削除できなくなる」が成立しないため
> （`.trash` への退避は同一ディレクトリの rename なので、保存が失敗する状況では削除も失敗する）。
> **いまの削除は捨てる前に書き戻す。** 以下の本文は当時の記録としてそのまま残す。

## 文脈

<!-- どんな問題・制約の中で決めたか。評価軸の優先度を先に書く（総合点方式の罠を避ける） -->

マイルストーン6（リネーム・削除）。前身（gpui 版）で払った授業料が 2 つある。

**1. `std::fs::rename` の二面性。** 宛先が存在しても黙って置換する。`save()` の
tmp → 本体のアトミック保存にはこの性質が必須だが、**同じ道具を移動に流用すると
後勝ちの上書きでノートが消える**。前身のデータ喪失欠陥 3 件（保存失敗後の遷移続行・
`Cmd+N` 同一秒連打・`.trash` 同名衝突）の共通の根がこれだった。

**2. 一覧から消える名前。** `load_dir()` は dot 始まりを走査から除外するので、
`.secret` へ改名したノートは再起動後に一覧から消える（前身で実際に踏み、修正済み）。

さらに、このアプリの表示タイトルは **frontmatter の `title:` > 本文の `# 見出し` >
ファイル名の stem** で決まる。つまり frontmatter を持つノートは**ファイル名を変えても
一覧の見た目が 1 文字も変わらない**。

評価軸の優先度:

1. **ノートを失わないこと**
2. 操作の結果が予測できること
3. `.md` が唯一の真実であること（表示のために本文を勝手に書き換えない）

## 決定

<!-- 何を選んだか1〜3行 -->

- **リネーム（`Cmd+R`）は「ファイル名だけ」を変える。** 本文には触らない。
  衝突は**枝番**（`-2`, `-3`）で逃がす。一覧から消える名前（空・`/`・`\`・dot 始まり）は拒否し、
  **拡張子が無ければ `.md` を補う**
- **削除（`Cmd+Delete`）は確認なしで vault 内 `.trash/` へ退避する。** 保存もしない
- 移動は `vault::move_to()` に閉じ込め、**`reserve_unique` で予約してから rename する**

## 却下した代替案

<!-- 何を・なぜ見送ったか。「なぜこれでないのか」が将来いちばん効く記録 -->

- **リネームで frontmatter の `title:` や `# 見出し` も書き換える**。一覧の見た目と一致するので
  分かりやすい。却下したのは、**表示のためにアプリが本文を書き換える**ことになるため。
  `.md` が唯一の真実という方針（ADR-0001）と衝突するし、`title:` を持たないノートに
  frontmatter を生やすか見出しを挿すかで、さらに勝手な判断が要る
- **リネーム先が既存名なら拒否する**。打った名前と違うものができない点は優れている。
  却下したのは `Cmd+N`・`.trash` と規則が割れるため。**衝突は枝番**で全経路を揃えた
- **拡張子なしの名前を拒否する**（dot と同じ扱い）。一貫はするが、`.md` を打たせる意味が無い。
  補えば済む
- **削除に確認ダイアログを出す**。`.trash` への移動は取り消せる操作で、確認は邪魔なだけ
  （前身と同じ判断）。**取り消せない操作になったら確認を足すこと**
- **削除の前に保存する**。`.trash` の中身が最新になる利点はあるが、捨てるノートを書き戻す意味が薄く、
  **保存に失敗したときに削除できなくなる**ほうが困る

## 帰結

<!-- この決定で背負うトレードオフ。非標準技術なら innovation token の消費として明記 -->

- **frontmatter を持つノートは、リネームしても一覧の見た目が変わらない。** 仕様どおりだが驚くので、
  入力欄にその旨を出している
- **`.trash` を空にする手段はアプリに無い。** Finder で消す（前身も同じ状態）
- 削除するとエディタの内容は破棄される。未保存分も含めて消える

## 学び

前身の教訓を移植するときは、**同じ理由で壊れる別の入口**を探す。dot 始まりは塞がれていたが、
`load_dir()` が `.md` しか拾わない以上、**拡張子落ちはまったく同じ理由で一覧から消える**。
前身はそこを塞いでいなかった。教訓は「dot を拒否する」ではなく
**「一覧から消える名前を作らせない」**と一般化して初めて穴が全部見える。
