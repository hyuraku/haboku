# ADR-0003: 等幅フォントに `Osaka-Mono` を名指しする

- 日付: 2026-08-09
- ステータス: 採用

## 文脈

<!-- どんな問題・制約の中で決めたか。評価軸の優先度を先に書く（総合点方式の罠を避ける） -->

エディタはコードブロックを含む Markdown をそのまま表示するので、等幅フォントが要る。
しかし移植検証で、**`Font::MONOSPACE` を指定すると
漢字が画面から消える**ことが分かっている。

`Font::MONOSPACE` は「等幅なら何でもいい」という**総称ファミリ**の指定で、実際にどのフォントが
当たるかは cosmic-text のフォールバックに委ねられる。macOS では漢字に `GB18030 Bitmap` が選ばれ、
Swash がラスタライズに失敗して `None` を返し、iced はそのグリフを黙って捨てる。
カナと英数字には別フォントが当たるので無傷のまま残り、**漢字だけが消える**。

症状は「長い日本語行が途中で切れて 1〜2 文字失われる」ように見える。真因にたどり着けたのは、
消えていたのが `言語` `重` `値` と**全部漢字**だったという文字種の共通点からだった。

評価軸の優先度:

1. **漢字が 1 文字も消えないこと**。Done の定義に明記されている
2. コードブロックの桁が揃うこと（等幅であること）
3. 追加の依存・配布物を増やさないこと（フォントを同梱しない）

## 決定

<!-- 何を選んだか1〜3行 -->

**`Font::with_name("Osaka-Mono")` で名指しする。** 総称ファミリ（`Font::MONOSPACE`）は使わない。

実データ 約 1200 件で目視確認済み: 漢字の欠落なし、コードブロックの桁が揃う。

## 却下した代替案

<!-- 何を・なぜ見送ったか。「なぜこれでないのか」が将来いちばん効く記録 -->

- **`Font::MONOSPACE`**。論外。漢字が消える。この ADR はそもそもこれを避けるためにある
- **Menlo / PT Mono / Andale Mono**。この Mac に入っている他の等幅だが、**どれも漢字を持たない**。
  英数字は等幅で出るが、漢字は毎回フォールバックに委ねられる。つまり
  `Font::MONOSPACE` と同じ賭けを、当たる確率だけ変えて続けることになる。
  さらに漢字と英数字で別フォントが混ざるため、そもそも桁が揃わない
- **フォント指定を外す（`Font::DEFAULT`）**。spike が漢字欠けを止めた方法で、確実に漢字は出る。
  却下したのはプロポーショナルだから。コードブロックの桁が揃わず、要求の 2 番目を満たさない
- **等幅 CJK フォント（HackGen・PlemolJP 等）を同梱する**。見た目は最も良くなるが、
  配布物にフォントを抱えることになり、ライセンス確認も要る。標準搭載で足りている今それを払う理由がない

## 帰結

<!-- この決定で背負うトレードオフ。非標準技術なら innovation token の消費として明記 -->

- **`Osaka-Mono` が入っていない環境では静かにフォールバックする。** cosmic-text は名前が
  解決できなくても失敗せず既定フォントに落ちるので、**漢字は出るが等幅でなくなる**という形で劣化する。
  漢字が消える方向ではないので事故ではないが、macOS 以外へ移すときは選び直しが要る
- 選定のために置いていた `HABOKU_FONT` の切り替えスイッチは削除した。**あれは足場であって機能ではない**

## 追記（2026-08-10）

**この ADR の「実データで桁が揃うことを確認済み」は成立していなかった。**
`"Osaka-Mono"` は PostScript 名で、cosmic-text（fontdb）が照合するファミリ名は `"Osaka"`。
つまりこの名指しは一度も解決されておらず、エディタはフォールバック（ASCII は比例幅）で
描画されていた。等幅グリッド（同じ字数の `0…9` / `i` / `W` / `l` の行）で行末が揃わないことを
確認した。漢字が欠けない点は事実のまま。経緯と検出方法は ADR-0009 の帰結を参照。
等幅の立て直しは別タスク。

## 学び

「等幅なら何でもいい」と書けてしまうインターフェイス（総称ファミリ）は、**選択をライブラリに委ねている**
ことを忘れさせる。委ねた先が CJK で失敗しても、失敗は例外ではなく**沈黙**（グリフを捨てる）として現れる。

そして今回の逆パターンも覚えておく価値がある。名指しに変えたあと「漢字が出ている」ことは
**フォントが効いている証拠にならない**。解決に失敗しても漢字はきれいに出るからだ。
効いているかどうかは、**桁が揃うか**でしか確かめられない。
