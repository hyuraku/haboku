# ADR-0017: undo / redo は全文スナップショットで自前に持つ

- 日付: 2026-08-13
- ステータス: 採用
- 関連: ADR-0016（`Ctrl+K` を入れたことで「戻せない」実害が具体化した）/ ADR-0014（保存はワーカー。undo も同じ dirty 経路に乗る）/ ADR-0002（開いた vault は常に書ける ＝ 書いたものを失わない）

## 文脈

<!-- どんな問題・制約の中で決めたか。評価軸の優先度を先に書く -->

**このアプリには「元に戻す」が無い。** そして戻せないことの実害は、`Ctrl+K`（行末まで切り取り）を
入れたときに具体化した — 1 打鍵で行の後半が消え、**自動保存が 1 秒後にそれをディスクへ届ける**。
`Ctrl+K` はクリップボードを戻し道にしたが（ADR-0016）、それは `Ctrl+K` にしか効かない。

依存の状況を先に確かめた:

| 層 | undo |
|---|---|
| iced 0.14 の `Binding` / `Action` / `Edit` | **無い**（`Undo` という語がソースに 1 つも無い） |
| cosmic-text 0.15（iced の下層） | **ある**（`Edit::start_change()` / `finish_change() -> Change`） |
| iced_graphics（両者の橋渡し） | **呼んでいない** |

つまり下層は差分記録を持っているのに、**iced が入口を塞いでいる**。`Ctrl+K` と同じ構図で、
アプリ側で持つしかない。

一方で、`Content` には**論理カーソルの取得と復元**がある:

```rust
pub struct Cursor { position: Position { line, column }, selection: Option<Position> }
pub fn cursor(&self) -> Cursor
pub fn move_to(&mut self, cursor: Cursor)
```

描画上の座標ではなく行・列なので、**本文を作り直したあとでも同じ位置へ戻せる**。

評価軸の優先度:

1. **開いていないノートの本文を書き込まない**（履歴の取り違えは、消えるのではなく「別の本文で上書き」
   という最悪の壊れ方をする）
2. 実用になる粒度（1 打鍵 1 ステップは使い物にならない）
3. 実装を最小に保つ

## 決定

**本文とカーソルの全文スナップショットを積む。**

- 区切りは**編集の種類が変わった瞬間**。連続入力は 1 ステップ、削除に変わったら新しいステップ
  （`EditKind`: Insert / Enter / Backspace / Delete / Paste / Indent）。**カーソルが動いたときも区切る** —
  切らないと行頭で打った文字と行末で打った文字が 1 回の undo でまとめて消える。
  スクロールは本文にもカーソルにも触らないので区切らない
- キーは **`Cmd+Z` / `Cmd+Shift+Z`**（macOS 標準）。既存の `Cmd+P` などと同じ subscription 経路で、
  `z` の本文混入は ADR-0010 のガードが防ぐ
- **パレット・リネーム欄が開いている間は効かせない。** そこへ打っているときの ⌘Z は
  「見ていない本文を書き換える」操作になる（ADR-0016 でフォーカスを見たのと同じ理由）
- **履歴の破棄は `replace_content()` に閉じ込める。** 本文を差し替える経路は 4 つ
  （起動・セットアップ完了・ノート切替・削除）あり、**1 つでも漏らすと切替後の `Cmd+Z` が
  前のノートの本文を今のノートへ書き込む**。差し替えの入口を関数 1 つに絞って、構造で防ぐ
- 上限は **100 段**。全文なので無制限だと「本文の長さ × 区切り数」で積み上がる
- **戻した本文もディスクへ書く**（`mark_edited`）。画面とファイルが食い違ったままだと、
  次に開いたときに戻したはずの編集が復活する。元の内容にちょうど戻った場合は、既存の
  「差分が無ければ書かない」判定が書き込みを省く

## 却下した案

- **cosmic-text の `Change` を使う（差分ベース）。** iced が公開していないので fork か patch が要る。
  それに、差分の適用・反転は自前で持つと状態管理が一段複雑になる。**このアプリは vault 全体
  （約 1200 件）を常時メモリに載せている**ので、1 ノート数 KB × 100 段は誤差
- **1 打鍵 1 ステップ。** 「あいう」を消すのに 3 回押すことになり、実用にならない
- **時間で区切る（手を止めたら区切る）。** 自動保存のデバウンスをそのまま使えて実装は最小だが、
  打ち続けている間の入力と削除が 1 ステップに混ざる。他のエディタと体感が揃わない
- **redo を作らない。** undo だけだと押しすぎたときの戻し道が無い。
  「安全装置は、失敗したときに何が起きるかまで設計する」（CLAUDE.md）の逆をいく

## 帰結

- 履歴を捨て損ねる事故は、**負のコントロールで実際に再現して確認した**（`replace_content` から
  破棄を外すと、切替後の `Cmd+Z` で「古い」ノートの本文が「新しい」ノートへ入る）
- undo は `Message::Edit` と同じ dirty 記録（`mark_edited`）を共有する。**片方だけ直す**と
  「戻したのに保存されない」か「無編集で mtime が動く」のどちらかが起きる
- `open_note` は本文を 1 度クローンしてから `replace_content` へ渡す（`&mut App` を取るため）。
  切替のたびに数 KB 余分に写すが、**打鍵ごとに走る経路ではない**
- **実機確認済み（2026-08-13）**: `Cmd+Z` で編集が戻ること、**長いノートの下のほうで undo しても
  スクロール位置が元のまま**であることを目視で確認した。`Content` を作り直す方式なので
  表示位置が飛ぶことを疑っていたが、スクロール位置は `Content` ではなくウィジェット側の
  状態にあるため影響を受けない
