# ADR-0015: vault の場所を初回セットアップ画面で決める

- 日付: 2026-08-11
- ステータス: 採用
- 関連: ADR-0002（読み込み専用モードの廃止。**「黙って別の場所を開かない」という判断をここでも守る**）

## 文脈

<!-- どんな問題・制約の中で決めたか。評価軸の優先度を先に書く（総合点方式の罠を避ける） -->

`.app` として配布する（`docs/review-2026-08-11-release-readiness.md` の「公開ラインに乗せる最短経路」）
にあたって、vault の場所の決め方が**そのままでは配布できない**形になっている。

1. **`VAULT` 環境変数が必須。** Finder / Dock から起動した `.app` は launchd 経由なので
   シェルの環境変数を一切継承しない。`vault_root()` は必ず `Err` になり `ExitCode::from(2)` で
   即終了する。**100% 起動失敗**する
2. **失敗が見えない。** `eprintln!` の行き先は Console.app で、ユーザーから見えるのは
   「アイコンが跳ねて消えた」だけ

そして「既定パスを決めて黙って開く」では済まない。macOS の TCC は `~/Documents` /
`~/Desktop` / `~/Downloads` を非サンドボックスアプリからも守っていて、**アプリが自分から
開こうとすると許可ダイアログが出る**。ここで拒否されると `load_dir` は空を返し、
**借り物の vault を指したつもりで空の画面が開く = ADR-0002 が避けたかった状態そのもの**になる。
逆に**ユーザーがフォルダ選択ダイアログで選んだ場所は暗黙に許可される**（Powerbox）。
つまりフォルダ選択は UI の意匠ではなく、**許可を受け取る手続き**でもある。

評価軸の優先度:

1. **書いたものを失わない・意図しない場所に書かない**（ADR-0002 を崩さない）
2. 初見の人が説明なしに保存先を決められる
3. 依存・配布物を増やさない（ADR-0003 / ADR-0013 と同じ）

## 決定

<!-- 何を選んだか1〜3行 -->

**解決順を `VAULT` 環境変数 → 設定ファイル → 初回セットアップ画面の 3 段にする。**
セットアップ画面は Boostnote に倣い、既定候補を提示しつつ選び直せる形にする。

- 画面は**アプリ内**に出す（OS のダイアログをいきなり開かない）。`~/Documents/haboku` を
  提示して **[この場所で始める]** と **[別の場所を選ぶ…]**（`rfd` の NSOpenPanel）の 2 択
- 決めた場所は `~/Library/Application Support/haboku/vault` に**パスを 1 行**書いて記憶する
- **記憶した場所が消えていたらセットアップ画面へ戻す。** 黙って既定パスへ倒さない
- `VAULT` 環境変数は最優先で残す（開発時に借り物 vault を指すため）。指定が不正なときは
  従来どおり即終了する — **明示的に指定されたものが外れているなら、代わりを探さない**
- `rfd` 0.17 を `default-features = false` で足す。innovation token 1 枚を払う

Boostnote の初回体験（保存先を最初に決めさせる / 既定を提示する / 後から選び直せる）に
合わせたのは、**この手のアプリで唯一前例のある形**だからで、意匠の好みではない。

## 却下した代替案

<!-- 何を・なぜ見送ったか。「なぜこれでないのか」が将来いちばん効く記録 -->

- **既定パスを自動作成して黙って開く（ピッカーなし）。** 実装は最小だが、TCC の許可ダイアログを
  拒否された瞬間に「空の vault が開く」に落ちる。**安全装置が失敗したときに何が起きるかまで
  設計する**という規律に照らして採れない（ADR-0002 と同じ穴）
- **既定パスをホーム直下 `~/haboku` にする**（Boostnote は `~/Boostnote` を作る）。TCC の
  保護対象外なので許可問題が構造的に消える。却下したのは、ホーム直下を汚さない方針に反する
  ため。**初回に必ず選択を経由させるなら `~/Documents` でも許可は通る**ので、
  ここで意匠を曲げる必要がない
- **ドラッグ&ドロップで受ける**（`iced_core` の `window::Event::FileDropped`。配線済みなのを
  `iced_winit-0.14/src/conversion.rs:338` で確認）。**借り物が増えないのが利点**だが、
  「空の画面にフォルダを落として初期設定」という前例が他のアプリに無く、他人に配るときの
  説明コストが高い。加えて**ドロップで TCC の暗黙許可が取れるかは未確認**で、取れなければ
  利点の半分が消える。確かめるコスト自体が rfd を足すコストを上回る
- **保存先の複数登録・切り替え**（Boostnote の特徴）。今の要求は「初回に 1 つ決める」で
  満たせる（BSSN）。spec の非目標のままにする
- **`Info.plist` の `LSEnvironment` で `VAULT` を渡す。** 環境変数の仕組みを変えずに済むが、
  保存先を変えるたびに `.app` の中身を書き換えることになり、ユーザーには不可視で触れない

## 帰結

<!-- この決定で背負うトレードオフ -->

- **起動経路が 3 つに増える。** テストで固定するのは優先順位そのものと、
  「記憶が壊れている / 指す先が消えているときにセットアップへ倒れる」こと
- **[この場所で始める] のほうは、まだ TCC のダイアログが出る余地がある。** この経路は
  `~/Documents/haboku` を**アプリが作る**ので、フォルダ選択を経由していない。ただし
  拒否されれば `create_dir_all` が失敗し、**セットアップ画面に理由が出て留まる**ので
  「空の vault が開く」には落ちない（`a_folder_that_cannot_be_created_keeps_the_setup_screen_with_a_reason`
  で固定）。実機で実際にどう出るかは公開前チェックリストで確認する
- **初回だけ vault 読み込みが iced の起動後になる。** 読み込み時間の計測点が 2 か所に増える
  （`main()` と、セットアップ確定時）。Done の定義の 50ms は暖機後の 2 回目以降で見る
- **`rfd` は macOS 以外では backend を持たない**（`default-features` を切ったため）。
  事実上 macOS 専用という性質が、初めて依存の形にも現れた。README に明記する
- **設定ファイルが「パス 1 行」なので、複数 storage が欲しくなったら形式を変えることになる。**
  その時に払う。今 JSON/TOML を選んでおくのは投機的な一般化（BSSN）

## 学び

**権限の仕組みが UI の形を決めることがある。** 「フォルダ選択ダイアログを出すか」は
使いやすさの問題だと思って比較を始めたが、実際には macOS から**ファイルを読む権利を
受け取れる唯一の経路**を選んでいた。UI の選択肢として並べている間は、
どちらも「やり方が違うだけ」に見えていた。
