# ADR-0009: 幽玄配色を 6 トークンで実装する

- 日付: 2026-08-10
- ステータス: 採用

## 文脈

<!-- どんな問題・制約の中で決めたか。評価軸の優先度を先に書く（総合点方式の罠を避ける） -->

意匠（幽玄・水墨画を下敷きにした配色とタイポグラフィ）は前段のデザインセッションで検討・承認済みで、
source of truth は公開 Artifact「幽玄 — haboku ビジュアルデザイン」
（`https://claude.ai/code/artifact/2df43c44-cf5f-410e-81da-94652570bc6a`）にある。
この ADR は**意匠の再検討ではなく**、それを iced 0.14 の実装へ落とすときに現場で決めたことの記録。

評価軸の優先度:

1. Artifact のトークン値・対応表を正とする（実装側で勝手に色を発明しない）
2. WCAG AA（文字は地に対して 4.5:1 以上）。意匠段階で監査済みの値を崩さない
3. 依存・配布物を増やさない（ADR-0003 と同じ。フォントも文法エンジンも同梱しない）

トークンは 6 つ + 派生値（アルファ違い）:
濃墨 `#18161A` / 淡墨 `#2A262C` / 生成り `#E9E3D5` / 霞 `#9E9689` / 琥珀 `#C89C62`（明るい側 `#D8B988`、
wash 14% / 26%）/ 枯茶 `#C17F4E`。琥珀だけが「今どこにいるか」の合図、枯茶は警告専用。赤・青は使わない。

## 決定

- `iced::Theme::custom` に 6 トークンを流し込む（background=濃墨、text=生成り、primary=琥珀、
  success=琥珀明、warning/danger=枯茶）。標準ウィジェット（text_input 等）はここから導出させる
- 選択中の行は `button::primary` をやめ、**琥珀の 14% wash 背景**の自前スタイルにする
- パレットの一致文字は `#D8B988` + セミボールド、エラーとステータスの警告は枯茶
- 見出しは `Hiragino Mincho ProN` を **`Weight::Light`（300）付きで名指し**する（下の帰結を参照）
- エディタのハイライトは `Base16Ocean` をやめ、**自前の Markdown ハイライタ**（`src/highlight.rs`）で
  frontmatter=霞・見出し=明朝・コード=琥珀明 の 3 区分だけを塗る

## 却下した代替案

<!-- 何を・なぜ見送ったか。「なぜこれでないのか」が将来いちばん効く記録 -->

- **赤系アクセント**。意匠段階で却下済み。墨と紙の世界観に赤は異物で、警告も枯茶で 4.5:1 を満たせる
- **フォント同梱（明朝・等幅 CJK）**。ADR-0003 と同じ判断。配布物とライセンス確認を抱える理由がない
- **syntect のカスタムテーマ**（`iced_highlighter` の差し替えを syntect 側でやる案）。
  `iced_highlighter::Theme` は閉じた enum でカスタム配色を受け付けず、syntect でやるには
  `two_face` 依存と ScopeSelectors の語彙を丸ごと抱える。このエディタが渡すトークンは常に `"md"`
  だけなので、全文法エンジンは過剰。3 区分の状態機械（100 行弱 + テスト）で足りる
- **霞を swatch 表記の `#948D84` にする**。Artifact 内で swatch の hex 表記と CSS 実体
  （`--kasumi: #9e9689`）が食い違っていた。**承認されたモックが実際に描画していたのは CSS 側**で、
  コントラストの余裕も大きい（淡墨に対し 5.1:1 vs 4.55:1）ため `#9E9689` を採用した

## 帰結

<!-- この決定で背負うトレードオフ。非標準技術なら innovation token の消費として明記 -->

- **cosmic-text 0.15 は、名指ししたファミリに要求と同じ weight の face があるときだけそれを使う**
  （`FontFallbackIter::default_font_match_key` が `font_weight_diff == 0` で絞る）。
  Hiragino Mincho ProN は W3（300）/W6（600）しか持たないので、既定の `Normal`（400）で要求すると
  **フォントが入っている環境でも**静かにゴシックへ落ちる。`Weight::Light` の名指しはこの回避で、飾りではない
- 明朝が無い環境では見出しがゴシックになるだけで、文字は欠けない（実機でフォールバック描画を確認済み）
- 自前ハイライタは CommonMark を網羅しない。塗り分けに必要な frontmatter・`#` 見出し・フェンス・
  インラインコードだけ。それ以外の記法（強調・リンク等）は本文色のまま
- **実装中の発見（別タスクへ申し送り）**: エディタ等幅の `Font::with_name("Osaka-Mono")` は
  **一度も解決されていなかった**。"Osaka-Mono" は PostScript 名で、fontdb が見るファミリ名は
  "Osaka"（比例・等幅の 2 face が同名・同 weight で並ぶ）。検証 vault の等幅グリッドで、ASCII が
  比例幅で描画されることを確認した。つまり ADR-0003 の「桁が揃うことを確認済み」は現ビルドでは
  成立していない。修正は選択肢の検討（fontdb の face 操作・別フォント・上流修正）が要るので
  この ADR のスコープ外とし、事実だけを ADR-0003 への追記とここに残す

## 学び

名指しに変えても「その書体で出ている」ことは確かめるまで信じられない、という ADR-0003 の学びの再演。
今回は落とし穴が 2 つあった: **ファミリ名と PostScript 名の取り違え**（Osaka-Mono）と、
**weight の完全一致条件**（Hiragino Mincho ProN）。どちらも失敗が沈黙（フォールバック描画）として
現れるので、「フォントが効いているか」は見た目の印象ではなく、**書体の判別できる拡大スクリーンショット**か
**桁揃えグリッド**で測る。今回それで両方を検出できた。
