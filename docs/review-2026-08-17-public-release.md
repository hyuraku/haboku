## 2. ブロッカー

### B-1. Cmd+Q が保存ガードを素通りする — 最大 2.5 秒分（保存失敗中は未保存の全部）が無警告で消える

**なぜ他人に害を与えるか。** macOS でアプリを終わらせる標準操作は Cmd+Q で、他人は Cmd+W より先に
必ずこれを踏む。通常時の被害はデバウンス〜上限の最大 2.5 秒分だが、**保存が失敗している間に
Cmd+Q を押すと、ADR-0012 で設計した 2 段階クローズ（警告 → `.rescue` 退避）が丸ごと素通りし、
未保存の本文が全部消える**。安全装置が一番要る場面にだけ穴が開いている。しかも docs は
「終了はガード済み」と主張しているため、利用者は守られていると信じて踏む。

**根拠。** `src/main.rs:450-455` は「`Cmd+W`・✕・`Cmd+Q`」が `CloseRequested` として届く前提で書かれ、
`src/main.rs:2437` の `exit_on_close_request(false)` + 保存ガードで受ける設計。
しかし winit 0.30.13 の macOS 実装では:

- `WindowEvent::CloseRequested` の発生源は `windowShouldClose:` **ただ 1 箇所**
  （`winit-0.30.13/src/platform_impl/macos/window_delegate.rs:143-148`。macOS backend 全域 grep で確認）。
  これを通るのは ✕ ボタンと Cmd+W（`performClose:`）だけ
- デフォルトメニューの Quit 項目は **`terminate:` セレクタ + key equivalent "q"**
  （同 `menu.rs:66-73`）で、NSApp を直接終了させる
- winit が実装するのは取り消し不能な `applicationWillTerminate:` のみで、
  終了を差し止められる `applicationShouldTerminate:` は未実装（同 `app_state.rs:69`、grep で確認）
- iced_winit 0.14.0 は `default_menu` を無効化しておらず（既定 true。`event_loop.rs:206,212`）、
  `terminate` への言及もゼロ

つまり Cmd+Q → `terminate:` → 即プロセス終了で、`CloseRequested` も保存もレスキューも走らない。
テスト（`closing_the_window_saves_pending_edits` ほか）は `CloseRequested` **以降**の経路しか
固定できないため、この OS 層の欠落は検出できない。

**確認水準: 実機再現済み（2026-08-17）。** 使い捨て vault + release ビルドに、PID 直指定の
CGEvent（`postToPid` — System Events 不使用。ユーザーの実インスタンスが同時に起動していたため
名前解決による誤送信を構造的に排除）でキーを送って確認した。手順は Cmd+N → Return×2 で dirty を
作り（IME の影響を受けないよう文字キーは使わない）、最後の編集から 0.2 秒後 = デバウンス 1 秒の
内側で終了操作。結果:

| 経路 | プロセス | 作られたノート |
|---|---|---|
| 放置（煙試験） | 生存 | 2 bytes（`0a0a` — 自動保存が書いた。計器の正当性確認） |
| ✕ ボタン（AX API で押下） | **0.4 秒で終了** | **2 bytes — 保存してから閉じた（ガード動作）** |
| Cmd+W | 生存（6 秒後も窓ごと残る） | 2 bytes（1 秒後の自動保存によるもの） |
| Cmd+Q | **0.2 秒で終了** | **0 bytes — 編集が消えた** |

**付随の新発見: Cmd+W は不発。** winit のデフォルトメニューには Close 項目が存在しない
（`menu.rs` 全域 grep。あるのは About / Services / Hide / Quit）ため、Cmd+W はメニューの
キーエコー先を持たず、窓は閉じない。データは消えないが、「Cmd+W で閉じられる」という
`src/main.rs:450` の主張も実態と食い違っている。

**解消の条件。** どちらかで閉じる:
(a) winit の `with_default_menu(false)` で自前メニューに置換する（Quit は close request へ流し、
ついでに Close 項目（Cmd+W → `performClose:`）を足せば Cmd+W の不発も一緒に直る）か、
objc2 で `applicationShouldTerminate:` を差して保存経路へ橋渡しする。
(b) 最低限の決着として、`src/main.rs:455` のコメント・`docs/spec.md:53` の終了行・README の
「保存が壊れない」節を実態に合わせ、「✕ は保存を待って閉じる。Cmd+W は効かない。Cmd+Q は
保存を待たずに即終了する」を既知の制限として明記する。(b) でも「約束と実態の食い違い」は
消えるので公開は可能になる。

> **追記（2026-08-18）**: (a) の方向で設計を確定し、**ADR-0021** に記録した（Quit 項目の
> action を `performClose:` へ付け替え + Cmd+W は Rust で `CloseRequested` に写像。
> 検討過程で `with_default_menu(false)` は iced 0.14 が公開しておらず不成立と判明）。
> **実装は未着手** — TODO は implementation-notes「次の一歩」の先頭。実装と実機ドライバ
> 3 経路の再検証が済むまで、このブロッカーは未解消のまま。
>
> **解消（2026-08-19）**: ADR-0021 を実装し、同じ手順の実機ドライバで再検証した。
> 3 経路すべてが「プロセス終了 + ノート 2 bytes（`0a0a`）」になり、
> **終了までの経過は 0.12〜0.14 秒**（= デバウンス 1 秒の内側）。この時間差により、
> 書いたのが自動保存ではなく**閉じる要求の保存ガード**だと分離できている。
>
> | 経路 | プロセス | 終了まで | ノート |
> |---|---|---|---|
> | 放置（煙試験） | 生存 | — | 2 bytes（自動保存。計器の正当性確認） |
> | Cmd+Q | **終了** | 0.12s | **2 bytes** |
> | Cmd+W | **終了** | 0.12s | **2 bytes** |
> | ✕ ボタン | **終了** | 0.14s | **2 bytes** |
>
> 併せて `Cmd+W` の写像を純関数に切り出してユニットテスト 4 本（写る / オートリピート無視 /
> 素の `w` は本文へ / `Cmd+Shift+W` は不発）で固定し、`src/main.rs` の `CloseRequested` の
> doc・`docs/spec.md` の終了行・README を実態に合わせた。**Dock 右クリックの Quit・
> ログアウト・AppleScript quit は引き続き対象外**（損失は自動保存上限の 2.5 秒以下に有界。
> 再導入条件は ADR-0021 の却下欄）。**B-1 はクローズ。**

**ブロッカーは以上の 1 件。** 秘密情報の混入・ライセンス問題・vault 外への書き込み・
外部入力起点のパニックは「無い」と断言する（根拠は §4 と §3 の各項）。

## 3. 公開してよいが直したほうがよい事項（優先順）

1. **ウェルカム画面は「打てるのに保存されない」**（ADR-0002 が廃止した経路と同型）。
   ノート未選択でもエディタは編集を受け付けるが（`src/main.rs:1998-2014`, `1554-1563`）、
   `mark_edited` は `selected` が無いと dirty を立てず（`src/main.rs:1030-1036`）、
   `begin_save` も未選択なら即抜ける（`src/main.rs:798-800`）。打った本文はノートを開いた瞬間
   `replace_content` で無警告に消える。→ **解消済み（2026-08-19、ADR-0022）**: 起動時に
   直近のノートを開き、未選択のときはエディタを画面に出さない。「未選択 ⟺ ノートが 0 件」が
   不変条件になった（読み取り専用にするより、状態そのものを消すほうが小さい）。
2. **最低 Rust バージョン 1.89 が README に無い。** README:24-25 は「edition 2024」（= 1.85 と読める）
   だが、Cargo.lock の font-types 0.12.2 が rustc 1.89 を要求（cargo metadata で機械確認。
   iced 0.14 / time 0.3.55 / plist 1.10.0 も 1.88）。1.85〜1.88 の読者は `cargo build` が即死する。
   → README に「Rust 1.89 以上」+ `Cargo.toml` に `rust-version = "1.89"`。
3. **「/」（ルート直下）で絞り込み中の Cmd+N が、ファイルシステムのルートへ書きに行く。**
   `create_note` の `app.root.join(folder)`（`src/main.rs:1108-1116`）に `ROOT_FOLDER = "/"`
   （`src/vault.rs:13`, `361`）が入ると、`Path::join` は絶対パスで全置換するため dir が `/` になる
   （rustc で確認: `PathBuf::from("/Users/x/vault").join("/")` は `"/"`）。macOS では / が読み取り
   専用なので「作成に失敗」止まりだが、/ が書ける環境では **vault の外**にノートを作る。
   `creating_while_filtered_uses_that_folder_and_keeps_the_filter` は `"notes"` しか試していない。
   → ROOT_FOLDER のときは `app.root` に作る分岐を 1 つ。
4. **プレビューのリンクを無検証のまま `/usr/bin/open` へ渡す**（`src/main.rs:1667`）。
   借り物ノートに仕込まれた `file:///…` や任意カスタムスキームがクリック 1 つで開く
   （シェルインジェクションは無い — `.arg()` の単一 argv 渡し）。→ `http` / `https` / `mailto` の
   allowlist に絞る。
5. **外部変更まわりの README 文言が実態よりやや甘い。** README:62-64 は「同時に開いて編集すると」
   と書くが、実際は**起動中の外部変更すべて**が対象: `notes` の `raw` は起動時に読んだきりで
   （`load_dir` は起動時のみ）、保存前の照合はメモリ比較だけ（`src/main.rs:806`）、外部で更新された
   ノートを開くと古い内容が表示される（`src/main.rs:1082`）。「haboku を開いたまま git pull」が
   危ないことが今の文面からは読み取りにくい。ADR-0007 自身が再導入条件 3 つを明記しており、
   公開すればそのどれかを満たす利用者が現れる。→ 文言の精密化（必要なら ADR-0007 に
   「他人に配る」を条件として追記して再判断）。
6. **病的な vault への耐性が無い。** `read_to_string` にサイズ上限が無く全 `raw` を常駐させるため
   2GB のファイルで OOM（`src/vault.rs:148-155`）、`walk` の再帰に深さ上限が無く数万段のネストで
   スタックオーバーフロー（`src/vault.rs:83-141`）。パニック経路・vault 外書き込みは監査済みで無いが、
   資源枯渇は防げない。README:48 が既存フォルダをそのまま開く使い方を勧めている以上、
   1 ファイル上限（超過は failed に計上）+ 深さ上限を。
7. **公開の外形の残り。** CI が無い（`cargo test` + `clippy` の macos ランナー 1 本で README 級の
   品質主張を第三者が検証できるようになる）、README:30 の `git clone <this repo>` プレースホルダ、
   `Cargo.toml` の `repository` 欄欠落。公開前に `cargo deny check advisories` も一度
   （cargo-deny は導入済み、要ネットワーク）。
8. **docs の数字の古び。** `docs/implementation-notes.md:668`「84 passed + 1 ignored」（実際は
   145 + 3）、`CLAUDE.md:9` が指す実データ vault（本機に既に存在せず — implementation-notes.md:20
   自認 — Done の再現手段が消えている）、`docs/spec.md:92` の M9「未着手」（README・LICENSE は済み）。
9. **残骸系の非対称。** 保存失敗時に `.md.<pid>.tmp` が残る（`src/vault.rs:186-213`。ADR-0007 で既知）、
   `move_to` の rename 失敗で空の予約 `.md` が残る（`src/vault.rs:275-279`。`write_rescue` は
   同じ状況で消している `:308` と非対称で、次回起動に空ノートとして出る）、保存成功の
   `app.error = None` が起動時の「N 件読めませんでした」警告まで消す（`src/main.rs:926`）。
10. **公開前の任意判断。** AI 共著 trailer と、個人の実データ vault を指すメタ情報は
    **2026-08-18 に履歴書き換えで処置済み**。残るは `.gitignore` に `.claude/` を足すこと
    （現在は `.git/info/exclude` 頼みで clone に伝播しない）。

## 5. 公開後に最初に来る指摘の予測

1. **ビルド失敗 Issue**:「requires rustc 1.89 or newer」。edition 2024 だけを見て 1.85〜1.88 で
   試した人が最初に踏む（§3-2）。
2. **「English README?」** README・エラーメッセージ・docs がすべて日本語。ターゲット定義
   （日本語で書く人）には正しいが、GitHub の Rust コミュニティからは最初に来る。
   対応方針（しないなら、しないと書く）を決めておくと楽。
3. **配布導線の要望**: バイナリリリースが無い・notarization 未対応・`cargo install` 不可・
   Homebrew は? — README は正直に書いているが、要望としては必ず来る。
4. **「Linux / Windows は?」** iced はクロスプラットフォームなので必ず聞かれる。macOS 専用の
   理由を README は 1 行しか書いていない（フォント名指し・テストの unix 依存・`/usr/bin/open`）。
5. **「Obsidian / VS Code と併用したら編集が消えた」**（§3-5）。前提を読まない利用者は必ず現れる。
6. **使い勝手系**: 新規ノートが日時名の羅列になる・`.trash` を空にできない・タグで絞り込めない
   （どれも implementation-notes「次の一歩」で自覚済み）。
7. B-1 を直さず公開した場合、status bar の saves カウンタに気づいた人からの **Cmd+Q 編集消失報告**。
