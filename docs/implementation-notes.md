### 本文検索: 予算を外してから 4 段の最適化で 20ms → 7.1ms（2026-08-15）

ADR-0018 の実装。**計測手段が無いまま入れたら、打鍵 1 回の `refilter` が 20ms だった。**
`view()` の 1ms は前から測っていたが、`update()` 側の予算はこのリポジトリに存在しなかった。

計測は合成コーパスで行った。**約 1200 件級の実データ vault が今このマシンに無い**
（実データ vault は不在、設定上の vault は 11 件・5KB）。`vault::Note` は全フィールド `pub` なので、
テスト内で `Vec<vault::Note>` を直接組み立てられる（ディスクには何も書かない）。乱数は使わない —
数字が揺れると段ごとの比較ができなくなる。

| 段 | 変更 | 最悪ケースの平均 |
|---|---|---|
| 0 | 素朴な実装 | 20.3ms |
| 1 | `lower()` で ASCII を早期 return | 17.2ms |
| 2 | `lower()` でかな・漢字を早期 return | 12.5ms |
| 3 | **走査を 1 パスに**（開始位置ごとにスライスを切り直すのをやめた） | 7.8ms |
| 4 | `Peekable` をやめて生の `CharIndices` + `can_voice()` で先読みを絞る | **7.1ms** |

最悪ケース＝**どこにも当たらないクエリ**。打鍵途中の未完成語がこれになるので、実使用で最も頻度が高い。

**一番効いたのは段 3（12.5 → 7.8ms）で、アルゴリズムではなく実装の粗さだった。**
開始位置を 1 文字ずらすたびに `&target[cursor..]` を作ってイテレータを初期化していた。
先頭が当たった位置でだけイテレータを複製する形にしたら、文字あたりの定数項が落ちた。
段 1・2 は「Unicode テーブル参照が重いはず」という読みで当てたが、効きは段 3 の半分だった。

**効かなかったもの**: `peek()` を濁点の付きうる文字だけに絞る変更は 7.77 → 7.83ms で誤差だった
（段 4 で `Peekable` ごと外して初めて効いた）。**当たりを付けた場所が外れることの方が多い。**

#### 予算は「平均」で定義した

当初 8ms を最悪値で置いたが、最悪値は回によって 7.3〜10.2ms とばらついた（他プロセスやサーマルの影響）。
打鍵のたびに走るものなので、体感を決めるのは連続した打鍵の均しであって 1 回の外れ値ではない。
`spec.md` の評価基準は**平均 8ms 未満**とし、最悪値は記録として出すだけにした。

実測（約 1200 件・本文 3.2MB・最大 212,773 文字のノートを含む・release）:

| クエリ | 平均 | 最悪 |
|---|---|---|
| 空クエリ（本文を読まない） | 0.050ms | 0.076ms |
| 1 文字（本文を読まない） | 0.172ms | 0.221ms |
| 大量に当たる（早期打ち切り） | 0.174ms | 0.216ms |
| 1 件だけに当たる | 7.340ms | 8.631ms |
| **どこにも当たらない** | **7.041ms** | 7.119ms |

回し方: `cargo test --release -- --ignored --nocapture`（**必ず `--release`**）。

### frontmatter パースの取りこぼしを消化した（2026-08-15）

同日の申し送り（下の「タグが画面に出ない件」節の表）に挙げた 6 件をすべて直した。
あわせて `vault.rs` に**1 本も無かった**パースのユニットテストを入れた。

| 直したもの | 変えた方針 |
|---|---|
| CRLF | `---\r\n` も frontmatter の開始として受ける。終端側は `find("\n---")` が `\r\n---` にも当たるのでそのまま。残る `\r` は `str::lines()` が落とす |
| `tags: rust` / `tags: a, b` | **括弧を必須にしない。** インライン分岐に入る条件から `[` を外し、括弧が無ければ値をそのままカンマで分ける |
| `tags: [a, b]  # コメント` | `]` より後ろを捨てる。括弧なしの側は `strip_comment()`（空白のあとの `#`）で落とす |
| `tags: ['a', 'b']` | タグ 1 つ分の掃除を `clean_tag()` に集め、`"` と `'` の両方を trim する |
| ブロック形式の途中の空行 | 空行では break しない。**キーの行（インデント無し）が来たときだけ**終わる |

**`#` は空白の後ろに限ってコメントとして扱う。** `#rust` のような値そのものを削らないため。
ただし `tags:  # あとで書く` のように値がコメントだけの行は、YAML どおりタグ無しにする
（これを入れないと「# あとで書く」というタグが一覧に出る）。

**テストが実装に依存していることを確認した。** CRLF 対応を外すと
`crlf_frontmatter_is_not_read_as_body` が `left: "n" / right: "メモ"` で落ちる
（title がファイル名フォールバックに落ちる）。**通ることではなく、外すと落ちることを見た。**

`scalar()` は今回も**行末コメントを落としていない**。`title: Rust # 入門` は
「Rust # 入門」のままになる。タグの 6 件に絞ったので手を付けていない。

### タグが画面に出ない件は「パース漏れ」ではなく「UI 未実装」だった（2026-08-15）

「frontmatter に `tags` を書いても反映されない」という報告を調べたところ、`vault.rs` は
`Note.tags` を正しくパースして詰めていた。**`tags` が `vault.rs` の外から一度も読まれて
いなかった**のが真因。`main.rs` のヒットは 1 件だけで、しかもテスト用の入力文字列
（`editor_roundtrip_is_byte_identical` の Markdown）だった。書き込まれるだけの実質デッドデータ。

**`cargo clippy` で捕まらない。** `Note` は `lib.rs` で `pub` 公開しているため、
未使用フィールドが dead_code 警告の対象外になる。bin + lib 構成では、公開型に足した
フィールドを「UI に配線し忘れた」ことを静的検査は教えてくれない。

対処は一覧の行（`note_pane`）とパレットの行に `tag_label()` の出力を足しただけ。
**パレット側はフォルダ名と同じ行に併記した**。行を足すとタグの有無で行の高さが変わり、
下で書くスクロール追従（相対オフセット）が前提を失うため。

#### 直さずに残したもの（今回のスコープ外・申し送り）

`vault.rs` の frontmatter パースには取りこぼしが 6 件ある。**どれも今回は直していない。**
`tags()` / `scalar()` / `split_frontmatter()` にはユニットテストが 1 本も無く、全部素通りしている。

> **追記（2026-08-15、同日中）: この表の 6 件はすべて解消した。** 下の
> 「frontmatter パースの取りこぼしを消化した」節を参照。行番号は当時のもの。

| 入力 | 現状の結果 | 該当箇所 |
|---|---|---|
| CRLF 改行のファイル | **frontmatter 丸ごと無視**（title・summary も巻き添え） | `vault.rs:391` の `strip_prefix("---\n")` |
| `tags: rust`（単一スカラー） | `[]` | `vault.rs:414-416` でインライン分岐に入れず、`:433` で break |
| `tags: rust, iced`（括弧なし） | `[]` | 同上 |
| `tags: [a, b]  # コメント` | `[]` | `vault.rs:415` の `strip_suffix(']')` が失敗 |
| `tags: ['a', 'b']` | `["'a'", "'b'"]` | `vault.rs:419` / `:432` が `"` しか trim しない |
| ブロック形式の途中に空行 | 空行以降が落ちる | `vault.rs:433` が空行で break |

**実害が一番大きいのは CRLF。** タグだけでなく title と summary も落ち、frontmatter が
本文として表示される。直すならここから。

タグまわりで未実装のものも残っている:

- **タグでの絞り込みが無い。** `visible_indices()`（`main.rs:518-525`）の条件はフォルダだけ。
  `spec.md` の非目標は「タグの付け外し専用 UI。**frontmatter にあるタグで絞り込めれば足りる**」
  と書いているのに、機能テーブルにタグの行が無い。**仕様側でも宙に浮いている**ので、
  入れるなら spec を直すのが先
- **検索がタグを見ない。** `fuzzy::match_query(query, &note.title)`（`main.rs:1277`）の
  対象はタイトルのみ。タグを含めるなら、ハイライトの `Match::ranges` が
  タイトル文字列のバイト範囲前提（`main.rs:1832-1858`）なので、タグにマッチしたときの
  range の扱いを先に決める必要がある

### パレットの選択が可視領域の外へ出ていた（2026-08-15）

`ctrl-n` で選択を下に送ると、ハイライトは動くのに**その候補が画面に見えない**という報告。
候補リストは `scrollable` でラップされていた（`main.rs:1910`）が、

- その `scrollable` に `Id` が付いていない
- `snap_to` / `scroll_to` / `scroll_by` が `src/` 全体に **1 箇所も無い**（grep 0 件）

ため、`palette.selected` が進んでもスクロール位置は 0 のまま据え置かれていた。
選択インデックスの範囲は `% len` で正しくクランプされており、そちらは無実。

**iced には「選択中の子へ自動スクロールする」仕組みが無い**（`snap_to_end` は末尾固定のみ）。
DOM の `scrollIntoView()` に相当するものが無いので、`update()` から明示的に `Task` を返す。
このリポジトリは `operation::focus` を既に 3 箇所で使っており（`main.rs:815, 1533, 1599`）、
作法は確立済みだった。**スクロール系だけが抜けていた。**

**絶対座標ではなく相対オフセットで出した**（`palette_scroll_offset`）。リストは
`height(Fixed(360.0))` だが 1 行の実測ピッチは約 43.9px で、`360 / 43.9 ≒ 8.2` 行。
高さが行数の整数倍でないので、絶対座標だと最下行が半端に切れる計算をどこかで持つことになる。
相対なら「末尾を選んだら最下部」が定義から出る。前提は「全行が同じ高さ」なので、
パレットのタイトルに `Wrapping::None` を付けて折り返しを止めてある。

あわせて `PaletteQueryChanged` でも先頭へ戻すようにした。これが無いと、絞り込み直後に
`selected = 0` だけ戻ってスクロール位置が残り、**「選択は先頭なのに先頭が上に隠れている」
逆の症状**になる。

### undo のテストで `flush_saves` が空回りしていた（2026-08-13）

ADR-0017 の実装中。`flush_saves` は **`app.saving` が `Some` のときしか動かない**（積まれた
保存を実行するヘルパーであって、保存を始めるものではない）。打鍵しただけでは保存は始まらないので、

```rust
type_text(&mut app, "X");
flush_saves(&mut app);          // ← 何もしない
assert!(!on_disk.contains('X')); // ← 書いていないので当然通る
```

という**何も検証しないテスト**を一度書いた。`Message::Tick(now + AUTOSAVE_DEBOUNCE)` で
保存を始めてから `flush_saves` を呼ぶのが正しい型。同型の罠がもう 1 つあり、dirty のまま
`NoteSelected` を送ると**切替が保存の完了まで待たされる**（ADR-0014）ので、
「切り替えたつもりで切り替わっていない状態」でテストが通ってしまう。

対処として、**前提そのものを assert するようにした**（「ディスクに X がある」「`selected` が
動いている」を先に確かめてから本題を見る）。前提が崩れたらテストは緑ではなく赤になる。

### `Ctrl+K` を「形」でテストして、効果が出ない実装を通した（2026-08-13）

`Sequence[Select(End), Cut]` で実装し、**Sequence の中身が正しいことをテストして満足した**。
実機では**選択されるだけで何も消えなかった**（利用者からの指摘で発覚）。

`Binding::Sequence` は状態を進めない — `Select` は publish するだけ、`Cut` はその場で
`content.selection()` を読むので、常に選択前の空を見る（詳細は ADR-0016）。

学び:

- **GUI の binding は「形」ではなく「本文がどう変わるか」で見る。** ADR-0016 の 1 巡目で
  `matches!(steps.as_slice(), [Select(End), Cut])` を通していたが、この形は**正しいまま**で
  効果だけが出ていなかった。`content.text()` を突き合わせるテストなら 1 巡目で落ちていた
- **「安全装置が効いた」と「安全装置が常時作動していた」は同じ見た目をする。** `Cut` が
  空選択で no-op になる性質を安全策として選んだが、実際にはその no-op が毎回起きていた。
  no-op を安全策に使うなら、**動くはずの場合に動くことを別途固定する**必要がある
- 負のコントロール（削除の手順だけ外す）で、実機の症状（`一行目\n二行目` のまま変わらない）が
  テストに再現することを確認した

### 敵対的レビューの 2 件を処置（2026-08-12）

キーバインドの調査（ADR-0016）と同じレビューで出た vault 読み込みの件。**片方は仕様違反だった。**

1. **`load_dir` が「読めなかった」を返せていなかった。** 戻り値が `Vec<Note>` なので、
   失敗は `eprintln!` に出るだけ。`.app` の利用者に stderr は見えないので、権限や I/O エラーで
   欠けた一覧が**「そういう vault」として見える**。`docs/spec.md` が「読めないファイルは黙って
   捨てず件数に出す」と書いてある以上、これは仕様違反。`vault::Load`（`notes` + `failed` +
   `first_failure`）を返す形に変え、常駐エラー行に出した
2. **`entries.flatten()` はエントリ単位の失敗を完全に捨てていた。** `read_dir` の失敗は
   拾っていたが、イテレータが返す `Err` は黙って消えていた（**数え漏らしの入口が
   もう 1 つあった**。2026-08-10 の外部レビューと同型）。明示の `match` に直した
3. **意図的に飛ばしているものは失敗に数えない。** dot 始まり・`node_modules`・symlink は
   仕様どおりの除外（symlink は ADR 相当の安全策）。ここを数えると毎回「1 件読めていない」と
   言い続ける狼少年になり、本物の失敗が埋もれる
4. **件数だけでなく 1 件目の理由も出す。** 「3 件読めませんでした」だけでは打つ手が分からない。
   全件持つと病的な vault で膨らむので、**最初の 1 件だけ**を例示として持つ

`boot()` のシグネチャは `Vec<Note>` → `vault::Load` へ変えた。2026-08-11 の判断
（テストを守るためにシグネチャを変えない）とは逆だが、ここは**読み込み結果から `App` を作る
唯一の場所**で、警告の組み立てをそこに置きたかった。呼び出し元の書き換えは 5 箇所。

### `.app` 化（マイルストーン 7）で現場判断した 3 点（2026-08-11）

ADR-0015 の実装中に決めたこと。ADR に書くほどではないが、理由がコードから読み取りにくいもの。

1. **`boot()` のシグネチャを変えず、設定ファイルのパスを `App` のフィールドに持たせた。**
   `config_file` を引数に足すと既存のテスト（`app_with_vault` 経由）を全部書き換えることになる。
   フィールドにしたのはテストのためでもある — `$HOME` を書き換えずに使い捨てのパスへ差し替えられる
   （環境変数はプロセス全体で共有なので、並列に走るテストから触ると互いを壊す）
2. **セットアップ中でも `CloseRequested` だけは通す。** `exit_on_close_request(false)`（ADR-0007）に
   してあるので、入口のガードで一律に落とすと**✕ も `Cmd+Q` も効かない窓**になる。
   保存するものがまだ無いので `close_window`（保存を挟む経路）ではなく素直に閉じる
3. **アイコンは Codex に生成させた**（`assets/make-icon.swift` + `make-icon.sh`。swiftc +
   CoreGraphics で、新しいツールも配布物も増やさない）。**`.icns` の生成までは向こうで
   終わっていなかったので、こちらでスクリプトを回して作った。** スクリプトは決定的
   （2 回走らせて PNG が同一バイト数）で、16px でも「濃墨の角丸に生成りの一筆」として読める

残件（**実機で人が触らないと確かめられないもの**）:

- **誤リネーム 3 経路の目視確認**（リネーム欄を開いたまま `Cmd+N` / 一覧クリック / `Cmd+P` 選択）。
  回帰テストでは固定済みだが、公開判定レビューが残した宿題は目視のまま
- **[この場所で始める] を押したときに TCC のダイアログが出るか**（ADR-0015 の帰結）。
  拒否したときにセットアップ画面へ理由が出ることはテストで固定してある

### ⌘ 混入の修正中に、`Cmd+N` がリネーム欄を畳まない事実を発見（2026-08-11）

ADR-0010 の実機確認でリネーム欄を開いたまま `Cmd+N` を押したときに気づいた。
`Message::NewNote`（`src/main.rs`）は `app.palette = None` でパレットは畳むが、
**`app.rename` は畳まない**。結果:

1. リネーム欄を開く（`Cmd+R`）
2. `Cmd+N` を押す → 新規ノートが作られ、フォーカスはエディタへ移る
3. **リネーム欄は開いたまま残る**（`view()` の stack に出続ける）
4. そこで Enter を押すと `Message::Key` の分岐がリネームの Enter を先に拾い、
   `RenameCommit` が走る。対象は `app.selected` なので、**さっき作られた新規ノートが、
   前のノートのファイル名でリネームされる**

その場で取った選択: **手を付けず記録に留めた。** ADR-0010 で直したのは
「⌘ 付きの打鍵が文字として混入する」件で、こちらは**オーバーレイの排他が抜けている**という
別の穴。同じコミットに混ぜると、どちらの検証も濁る。混入の修正後も再現する。

申し送り: **`NewNote` だけの話ではない。** `app.selected` を動かす経路を数えると、
`DeleteNote` は両方畳んでいる（`app.palette = None` / `app.rename = None`）のに対し、
`NewNote` はパレットしか畳まず、`NoteSelected`（一覧クリック）は**どちらも畳んでいない**。
リネーム欄を開いたまま一覧の別ノートをクリックしても、同じ「開いたままのオーバーレイが
別のノートを指す」状態になる。

直すなら 1 箇所ずつ潰すのではなく、「エディタを上書き／破棄する経路を全部数える」
（ADR-0007 の学び）と同じ数え方で、**`app.selected` を動かす操作**を先に列挙すること。

**解決（2026-08-11）**: 申し送りどおり `app.selected` を動かす操作を列挙した
（一覧クリック・パレット Enter・`Cmd+N`。`DeleteNote` は畳み済み）。経路ごとに畳むのではなく、
3 経路の合流点である `open_note()` で `app.rename` を畳む — 次に `selected` を動かす経路を
足しても同じ穴が開かない。あわせて `Cmd+P` でパレットを開くときも畳む（`RenameStarted` が
パレットを畳むのと対称。両方開くと `Message::Key` の分岐がリネームの Enter を先に拾い、
パレットの Enter が選択として届かない）。回帰テスト 3 本
（`creating_a_note_closes_an_open_rename` / `selecting_a_note_closes_an_open_rename` /
`opening_the_palette_closes_an_open_rename`）は、**修正を外して 3 本とも落ちることを
確認してから**固定した。実機での 3 経路の目視確認は公開前チェックリストに残っている。

|------|------|
| 保存が元ファイルの権限を捨てる（`0600` → `0644`） | **修正**（ADR-0011） |
| 退避に失敗しても閉じて本文を捨てる | **修正**（ADR-0012） |
| 保存失敗後、同期保存を 10Hz で無制限に再試行 | **修正**（ADR-0012。バックオフのみ。非同期化はしていない） |
| 外部編集を検知せず古い本文で上書きする | **非採用**。ADR-0007 の却下を維持（下記） |

**外部編集の検知を入れなかった理由。** 運用が「`~/Documents/haboku` の `.md` を haboku だけで
触る」で、外部エディタ（VS Code・Zed）や別プロセスからの書き込みを想定しないことを
ユーザーに確認した。競合検知が効くのは haboku が開いている間に別プロセスが同じファイルを
書き換える場合だけなので、この運用ではその経路自体が存在しない。
入れ直す条件 3 つは ADR-0007 の「再確認（2026-08-11）」に書いた。

**申し送り: 保存の同期 I/O は UI スレッドに残っている。** バックオフは「失敗が続く間に
固まる頻度」を 10Hz から最長 30 秒に 1 回へ落とすだけで、**1 回あたりの
`sync_all()` は UI イベント処理の中で走る**。遅い vault（ネットワークドライブ・
外付けの回転ディスク）では成功時にも引っかかる。直すなら `Task::perform` で
スレッドへ出すことになるが、`save_now()` の戻り値「エディタの内容を破棄してよいか」が
同期であることに全ガード（切替・作成・リネーム・削除・終了）が乗っているので、
**1 件の修正ではなく設計変更**として立てること（ADR-0012 の却下した代替案）。

なお `cargo test` / `cargo clippy --all-targets` はレビュー時点の HEAD でも通っていた
（レビューログの exit 101 はローカルで再現せず）。修正後は 78 passed / 警告なし。

### マイルストーン1: `lib.rs` を挟み、bench 専用 bin を作らなかった（2026-08-09）

### マイルストーン2/3: 一覧は更新日時順にしたが、**保存後は並べ替えない**（2026-08-09）

`vault.rs` のコメントに残っていた「mtime は毎回 stat するとコストなので path 順で妥協する」を
覆した。どのみち全ファイルを読んでいるので、`File::open` した**ハンドルから** metadata を取れば
追加コストは `fstat` だけで済む（`std::fs::metadata(path)` を別に呼ぶとパス解決をやり直す）。

実測: title 順 32.8〜38.0ms → **mtime 降順 32.4〜34.1ms**。誤差の範囲で、予算 50ms に対し余裕がある。

ここで計画に無かった罠が出た。**保存のたびに並べ替えると、編集中のノートが毎回一覧の先頭へ飛ぶ。**
`selected: usize` の指す先がズレるうえ、打鍵のたびに一覧が踊る。よって
**並べ替えは読み込み時だけ**とし、保存後は `modified` の値だけ更新して順序は動かさない。
順序が更新されるのは次回起動時でよい。

同時刻はタイトル順に倒す。一括生成や `git checkout` で mtime が揃うことがあり、
そこで順序が実行ごとに変わると「一覧が勝手に踊る」ように見える。

### マイルストーン2/3: spike から持ち込まなかったもの

spike には動く実装が丸ごとあるが、**今の要求に無いものは持ち込まない**（BSSN）。

- **`pane_grid` を使わず `row!` + 固定幅**。ドラッグリサイズは要求に無い。3 ペインが並べば足りる
- **キー購読（`event::listen_with`）を入れない**。ショートカットは M4 のパレットからで、
  M2/M3 の subscription は自動保存の tick だけ。持ち込む量が減る
- **パレット・`rich_text` ハイライトは M4 のもの**。`fuzzy.rs` は移植済みだが呼んでいない

### マイルストーン3: `should_save()` を純粋関数に切り出した

`update()` に時間比較を直接埋めると、境界を確かめるのに実時間を待つしかない。
`should_save(now, last_edit, dirty_since) -> bool` に切り出したので、`Instant` を組み立てるだけで
デバウンス・上限・その手前の 3 境界をテストできる。

退行の目印として **「`dirty_since` を打鍵のたびに更新すると上限が永遠に来ない」** を明示するテストを
置いた。この関数の正しさは**呼び出し側の記録の仕方**に依存するので、関数だけ見ても守れない。

### マイルストーン3: `Content::text()` の往復がバイト一致することをテストで固定した

「無編集の切替で mtime が動かない」は、`text_editor::Content` に入れて出した文字列が
元ファイルと 1 バイトも違わないことに依存する。ずれていれば `save_now()` の差分判定が常に外れ、
**開くたびに書く**アプリになる。iced 0.14 では往復が一致することを確認し、テストで固定した。

末尾改行が無いケースも入れてある。実 vault 約 1200 件は全ファイルが改行で終わっていて今日は
踏まないが、他ツールや将来の `Cmd+N` が改行なしのファイルを作った瞬間に化ける。
**境界はデータの現状ではなくコードで押さえる。**

なお型注釈が必須（`let content: text_editor::Content = ...`）。`()` も `text::Renderer` を
実装しているため注釈が無いと推論が決まらず、しかも `()` は何もしないダミーなので
うっかり通すと**検証にならないテスト**ができあがる。

### マイルストーン2: 等幅フォントは `Osaka-Mono` に確定（2026-08-09）

実データ 約 1200 件を表示して目視で確認。**漢字の欠落なし・コードブロックの桁が揃う。**
選定のために置いていた `HABOKU_FONT` の切り替えスイッチは削除した（足場であって機能ではない）。
理由と却下案は ADR-0003。

判断で効いたのは **「漢字が出ている」は等幅が効いている証拠にならない**という点。名前が解決できなくても
cosmic-text は既定フォントに落ちるだけで、漢字はきれいに出る。効いているかは**桁が揃うか**でしか分からない。

### マイルストーン3: 手打ちで確かめるはずだった 3 項目をテストに落とした（2026-08-09）

当初は「GUI で打って `saves` カウンタを見る」つもりだったが、`update()` はただの関数なので、
`Message::Edit` と `Message::Tick(未来の Instant)` を渡せば**時間を待たずに同じ経路を通せる**。
手で確かめると「たまたま動いた」を証拠にしてしまうので、3 つとも自動化した:

- `autosave_writes_after_debounce` — 編集して手を止めたらディスクに届く
- `switching_without_editing_does_not_touch_the_file` — **無編集の切替で mtime が動かない**
- `failed_save_blocks_the_switch_and_keeps_the_text` — ディレクトリを `0o555` にして
  実際に保存を失敗させ、切替が中断され本文がエディタに残ることを確認

**失敗系は失敗させないと検証できない。** 3 つ目は本物の権限エラーを起こしている。

### 環境まわりで踏んだもの: 同名の古いプロセス

`target/` に前セッションのビルド成果物（`haboku.app`）が残っていて、そこから起動された
プロセスが生き残っていた。`.app` の中身と `cargo run` のバイナリは**実行ファイルのパスが違う**ので、
`pkill -f 'target/release/haboku'` は `.app` 側のプロセスに当たらない。
「起動しているのに画面に出ない」の正体はこれ。

手がかりは `ps` の実行ファイル名が `(haboku)` と**丸括弧付き**だったこと（実行ファイルが削除済み）。
同名の別物を疑うときはプロセス名ではなく**実行ファイルの絶対パス**（`ps aux` の 11 列目）で見る。

### マイルストーン4: パレットは全ノートを探し、開いたら絞り込みを解除する（2026-08-09）

`Cmd+P` は「どのフォルダにいても目的のノートへ飛ぶ」道具なので、検索対象はフォルダ絞り込みを
無視して**全ノート**にした。ここで計画に無かった穴が出た。別フォルダのノートをそのまま開くと、
**選択中のノートが左の一覧に存在しない**状態が生まれる（一覧はフィルタされたままなので、
選択のハイライトがどこにも無い）。

よって**パレットから開いたときはフォルダ絞り込みを解除する**。「開いたノートは必ず一覧に見える」を
保つほうが、絞り込みを維持するより説明しやすい。テストで固定した。

閉じ方の設計は ADR-0004。トグルにできない制約が理由。

**パレットからの `Enter` にも保存ガードを通した。** 一覧クリックだけ守ってパレットを守り忘れると、
同じデータ喪失の経路が裏口から復活する。しかも失敗時は**パレットを閉じない** — 閉じてから中断すると、
なぜ切り替わらないのかがユーザーから見て分からなくなる。

## `view()` 構築時間の実測（2026-08-09 / release / 実データ 約 1200 件）

Done の定義「打鍵時の `view()` 構築が 1ms 未満」を本体で計測した。
条件は**最も重くなる側**に寄せてある（vault 内で最大の 212,564 文字のノートを開いた状態）。

| 条件 | 平均 | 最悪 |
|---|---|---|
| 一覧のみ（約 1200 件のボタンを毎回構築） | 0.155ms | 0.292ms |
| パレット表示中（上位 50 件 + スクリム） | 0.145ms | 0.189ms |

**1ms に対して 3〜6 倍の余裕がある。** 仮想リストは要らないという spike の結論が本体でも成立した。

計測は `#[ignore]` 付きのテストとして残してある（実データが要るので既定では走らせない）:

```
VAULT="$HOME/Documents/haboku" cargo test --release -- --ignored --nocapture
```

併せて `view()` の所要時間を**画面のステータス行に常設**した。前身の落とし穴1
（`render()` にタグ集計を置いて打鍵ごとに全ノート走査）は、数字が見えていれば書いた瞬間に
気づけた性質のもの。`view()` は `&App` しか取れないので `Cell<u128>` で内部可変にしている。
表示は 1 フレーム前の値（構築中の時間は構築が終わるまで確定しない）。

### マイルストーン5: 先頭への差し込みでインデックスが全部ずれる（2026-08-09）

新規ノートは**いま絞り込んでいるフォルダ**（無ければ開いているノートと同じフォルダ）に作り、
**一覧の先頭**に差し込み、**エディタへフォーカスを移す**（作った直後に打ち始められる）。

置き場所の優先順位は最初「開いているノートと同じフォルダ」を先に置いていたが、**実際に触って
逆にした**。`topics` のノートを開いたまま `notes` で絞り込んで `Cmd+N` すると `topics` に作られ、
それを見せるために絞り込みが解除される（＝一覧がすべてに戻る）。設計時に
「2 つが食い違ったときどちらが勝つか」を詰めていなかったのが原因で、**見ているフォルダに増える**
ほうが期待に近い。優先順位を入れ替えると、絞り込みを解除する必要そのものが消えて動きも単純になった。

一覧は読み込み時の順序で固定しているので、先頭に差し込む以外の選択肢が実質無い。
末尾だと 約 1200 件スクロールした先に出て「作ったのに見えない」になる。

そして先頭への差し込みは **`notes` の全インデックスを 1 つずらす**。`selected` の付け替えを
忘れると「作成した瞬間に、開いていたノートが隣のノートにすり替わる」という、再現条件の
分かりにくいバグになる。回帰テストとして固定した
（`creating_a_note_does_not_swap_the_previously_open_note`）。
パレットが開いていれば `matches` も古いインデックスを指すので、作成時に畳む。

作成先が絞り込みの外になる場合（topics のノートを開いたまま notes で絞り込んで `Cmd+N`）は、
**絞り込みを解除する**。パレットから開くときと同じ規則で、「作ったノートは必ず一覧に見える」を保つ。

`Cmd+N` にも保存ガードを通した。作成もエディタを上書きする操作なので、
一覧クリック・パレットと同じ扱いにしないと裏口が開く。

### マイルストーン5: 実機で 3 件出た。どれも「`notes` を変えたときの連動漏れ」（2026-08-09）

テストは通っていたのに、触った瞬間に 3 つ出た。**個々の機能は正しく、連動が抜けていた。**

| 症状 | 実体 |
|---|---|
| 絞り込み中に `Cmd+N` すると一覧がすべてに戻る | 作成先の優先順位が「開いているノート > 絞り込み」で逆だった |
| 絞り込み中にパレットで**同じフォルダの**ノートを開くとすべてに戻る | 絞り込みを**無条件に**解除していた |
| 作ってもサイドバーのフォルダ件数が増えない | `folders` を起動時に 1 回数えたきり更新していなかった |

上 2 つは同じ間違いで、**守りたい不変条件（「選択中のノートは必ず一覧に見える」）と、
それを守る手段（「絞り込みを解除する」）を取り違えていた**。不変条件が既に満たされているときは
何もしないのが正しい。いまは `hidden_by_filter` の条件式で「破れるときだけ」に揃えてある。

3 つ目を機に、`notes` から導かれる状態（`folders` と `visible`）を **`refresh_derived()` の
1 箇所に集約**した。派生状態が 2 つあると片方だけ更新するコードが書けてしまう。
**`notes` を変更したら必ずここを通す。** M6（削除）で同じ穴を開けないための構造的な予防。

なぜテストで捕まらなかったか: **連動漏れそのものを検査するテストが無かった**。
個々の機能（作成できる・絞り込める・件数が出る）は全部通っていた。3 件とも回帰テストを足した。

### マイルストーン5: 空ノートの往復も固定した

`Cmd+N` が作るのは**空ファイル**なので、`Content::with_text("")` が `"\n"` を返す実装だと、
作った直後に開いて閉じるだけで書き込みが走る（`saves` が増え、mtime が動く）。
iced 0.14 では空のまま返ることを確認し、テストで固定した。

### マイルストーン5: 継承した判断の根拠が消えていた

ファイル名の生成に日時が要るが std にローカル時刻が無い。前身は `chrono::Local` を使い、
理由を「gpui-component の依存に既に入っているので追加ダウンロードは発生しない」と書いていた。
**iced ではこの理由が成立しない。**

依存ツリーに既にある `time` 0.3 を使おうとしたが、`local-offset` は**マルチスレッドで
`IndeterminateOffset` を返す**（健全性のための意図的な設計）。iced は確実にマルチスレッドなので、
「動くように見えて実行時に必ず失敗する」選択肢だった。結論は chrono を足す（ADR-0005）。

**継承した判断は、根拠ごと継承されているか確かめる。** 前身のコメントに理由が書いてあったから
気づけた。理由の無いコードだったら、そのまま持ってきて依存だけ増やしていた。

### マイルストーン6: 「リネームの二面性」は rename システムコールの話だった（2026-08-09）

着手前に前身の AGENT_NOTES を読んで、**自分の理解が間違っていた**ことが分かった。
「リネームの二面性」を「ファイル名の変更とタイトル行の変更は別物」の意味だと思っていたが、
実際は **`std::fs::rename` の二面性**だった:

> 宛先が存在しても黙って置換する。tmp → 本体のアトミック保存にはこの性質が必須だが、
> 同じ rename を衝突回避（新規作成・`.trash` 移動）に流用すると後勝ちの上書きでデータが消える。

前身のデータ喪失欠陥 3 件の共通の根がこれ。**着手前に一次資料を読む指示（CLAUDE.md）が
そのまま効いた**格好で、読まずに書いていたら移動のたびに rename を直接呼んでいた。
移動は `vault::move_to()` に閉じ込め、`reserve_unique` で予約してから rename する。

### マイルストーン6: 前身が塞いだ穴の「同型の入口」がもう 1 つあった

前身は dot 始まりのリネームを拒否していた（`load_dir()` が dot 始まりを走査から除外するため、
`.secret` に改名すると再起動後に一覧から消える）。

**同じ理由で壊れる入口がもう 1 つある。** `load_dir()` は `.md` しか拾わないので、
`設計メモ`（拡張子なし）へのリネームも**まったく同じ理由で**一覧から消える。前身は未修理だった。
拒否ではなく `.md` を補う形で塞いだ。

教訓は「dot を拒否する」ではなく **「一覧から消える名前を作らせない」**と一般化して初めて
穴が全部見える。移植では、前身が塞いだ穴そのものより**同じ理由で開く別の穴**を探すほうが効く。

設計判断（ファイル名だけ変える・衝突は枝番・削除は確認なし保存なし）は ADR-0006。
**うち「保存なし」は ADR-0007 で取り消した**（下記）。

### 外部レビュー: ガードは作ってあったが、経路を数え漏らしていた（2026-08-10）

マイルストーン 1〜6 が終わった時点で、コード全体（2361 行）を外部の目（Codex）に読ませた。
指摘は 9 件。**内訳の見立てが、レビューの受け取り方としてそのまま教訓になった。**

| 判定 | 件数 | 中身 |
|---|---|---|
| 本物 | 6 | 終了時の未保存喪失 / `show_marker` 到達不能 / symlink 追跡 / fsync 無し・tmp 名固定 / fuzzy の dead 分岐 / 削除時の未保存喪失 |
| 意図的（doc 化済み）で却下 | 2 | `view()` の `Cell`（恒久の計器）/ 削除時の破棄（→ 議論の末この 1 件は採用に転じた） |
| 本物だが不採用 | 1 | 外部変更の上書き検知（メモ帳なので前提を置かない。ADR-0007） |

**いちばん重い 1 件（終了時）は、既にある仕組みの数え漏らしだった。** `save_now()` は
「エディタの内容を破棄してよいか」を返す設計で、切替・作成・リネームには通してあった。
抜けていたのは削除と終了。**「ガードを作った」で満足せず「エディタを上書き／破棄する経路」を
列挙して照合していれば、レビューを待たずに見つかった。**

**安全装置が 2 つとも、定数や正規化の順序だけで無効化されていた。**

- `show_marker`: 判定が `if should_save {} else if marker {}` の排他で、
  `DIRTY_MARKER_DELAY(3000ms) > AUTOSAVE_MAX_WAIT(2500ms)` である以上、marker の条件が真になる
  ときは save の条件も必ず真。**「異常のシグナル」と doc に書いた表示が、異常時こそ点かない**
- `fuzzy::is_word_boundary` の camelCase 判定: `fold()` が `lower()` を通したあとの文字を
  渡していたので `cur.is_uppercase()` は原理的に false。**判定に要る情報を、判定の前に潰していた**

どちらもテストが無かったのではなく、**「点かないこと」を確かめるテストが書けていなかった**。
今回は失敗を実際に起こして（権限を落として）点灯を固定した。

`.rescue` の 2 段階（1 回目は断る / 2 回目は退避して閉じる）に至った経緯は ADR-0007。
**「本文を守るために閉じない」は、ユーザーに残る手段（強制終了）まで数えると最悪の結果になる**
というのが決め手だった。ADR-0002 で廃止した読み込み専用モードと同じ形の罠。

### 外部レビュー 2 巡目: 公開判定で high 3 件（2026-08-11）

Codex の敵対的レビューを「本番公開できる品質か」で走らせ、high 3 件を処置した。
3 件とも**前の周回で「今回は見送る」と自分で書いた場所**か、その修正が届いていなかった場所。

1. **新規ノートと `.rescue` が `0644` で生まれていた。** ADR-0011 で「保存は元ファイルの
   権限を引き継ぐ」を入れたが、`reserve_unique` が作る**予約ファイル**は umask 任せのまま
   だった。`move_to` 経由なら直後の rename で inode ごと消えるので無害だが、
   新規ノートと `.rescue` は予約したその inode に書き続けるので、そこが最終的な公開範囲になる。
   しかも `save()` は元の権限を引き継ぐので、新規ノートは**初回の `0644` を永久に引きずる**。
   → `.mode(0o600)` で予約。「保存が公開範囲を広げてはいけない」なら**作成も広げてはいけない**
2. **`Osaka-Mono` が一度も解決されていなかった件の決着。** ADR-0003 追記の宿題。
   `"Osaka"` に直す案も含めて却下し、`BIZ UDGothic` にした（ADR-0013）。
   判定は目視ではなく `name` / `hmtx` / `OS/2` を直接読んだ数字と、fontdb への実問い合わせ
3. **同期 `sync_all` が UI スレッドを止めていた。** ADR-0012 の却下欄に
   「本筋の解だが今回は大きすぎる」と書いて見送った件。**公開という判定基準が入った時点で
   評価が反転した**ので採用に転じた（ADR-0014）

**この 3 件に共通するのは「前の周回の申し送りが、次の周回で high に育っている」こと。**
却下欄と Deviations に理由まで書いてあったおかげで、どれも文脈の再構成なしに実装へ入れた。
記録の値打ちが出たのはここ。

残件: **実機の目視確認**（`BIZ UDGothic` での日本語表示・等幅グリッド、
遅い/書き込み不能ストレージでの UI 応答）はまだ取れていない。数値と単体テストで
裏は取れているが、Done の定義が要求する「実データでの目視」は未消化。

## 学び・ハマりどころ

<!-- 同じ穴に二度落ちないためのメモ。2回説明した手順は .claude/skills/ へ切り出す -->

前身と移植検証で払った授業料。**同じ穴に落ちないこと。**

### iced 固有

- **`Font::MONOSPACE` を指定すると漢字が消える。** cosmic-text が漢字に macOS の `GB18030 Bitmap` を
  選び、Swash がラスタライズに失敗してグリフごと捨てられる。カナと英数字は別フォントが当たるので無傷。
  症状は「長い行が途中で切れて 1〜2 文字失われる」ように見えるが、消えるのは**漢字だけ**。
  等幅にするなら漢字が出るフォントを名指しし、漢字入りの実データで必ず確認する
- **`keyboard::listen()` は `Status::Ignored` のイベントしか流さない。** `text_input` にフォーカスが
  あるとショートカットが届かない。グローバルショートカットは `event::listen_with()` を使う
- **subscription はイベントを観測できるが消費できない。** `Cmd+P` を拾って閉じても、同じイベントが
  `text_input` にも渡って "p" が挿入される。トグル型のショートカットは成立しないので、
  閉じる操作は Escape / ✕ / 背景クリックに寄せる
- **`Fill` の隣に可変長の表示を置くと本文がずれる。** ステータス表示の桁数が変わると高さが動き、
  「打った文字が1つ上の行に入った」ように見える。高さを固定する
- **`iced::time::every` は `tokio`（か `smol`）feature が要る。** 足すまで名前解決に失敗する

### この題材で普遍的なもの（フレームワークを替えても効く）

- **毎フレーム走る場所に集計を置かない。** 前身では `render()` の中でタグ集計をしていて、
  1 文字打つたびに全ノートを走査していた。iced でも `view()` に置けば同じ穴が開く
- **保存に失敗したら遷移を中断する。** `save_now()` の戻り値は「エディタの内容を破棄してよいか」。
  false で進むと未保存の本文がディスクにもメモリにも残らない
- **`dirty_since` は false → true の遷移でだけ記録する。** 打鍵のたびに更新すると
  「打ち続けている間の経過時間」が測れず、保存間隔の上限に永遠に到達しない
- **内容が変わっていなければ書かない。** カーソルを動かしただけで mtime が動くと、外部ツールから
  「更新された」と誤認される。保存回数のカウンタを画面に出しておくと即座に気づける

### 調査の型

- **GUI のバグを見たら、状態と表示のどちらが壊れているかを数字で先に分ける。** 前身では
  「元ファイル 2192 文字 = 画面の文字数 2192」の照合で、疑う層をレンダリングだけに絞れた
- **「どこで壊れたか」より「何が壊れたか」を先に見る。** 日本語欠落の件では折り返し位置との相関に
  引きずられて 2 つ仮説を外した。消えていたのが全部漢字だという文字種の共通点が真の手がかりだった
- **失敗系は失敗させないと検証できない。** 正常系だけ試していると「保存失敗時に遷移を中断する」ガードが
  効いているか永遠に分からず、実際に壊れた日にデータを失って気づくことになる
- **同じコードが違う数字を出したら、まず計測環境を疑う。** vault 読み込みが 168ms と出て焦ったが、
  ディスクキャッシュが冷えていただけだった（暖機後 30ms）
