## 問い 1: 公開できる完成度か — **足りていない（コード本体ではなく、リポジトリの外形が理由）**

コードとテストの品質は公開水準。足りないのはその外側の 3 点。

1. **README・LICENSE・配布導線が無い。** ライセンス無し = 法的に他人は使えない。
   起動手順（`VAULT` 必須・release 必須）は `src/main.rs:2-6` の doc コメントと CLAUDE.md にしか無い。
   `Cargo.toml` は `publish = false` でメタデータ無し。
2. **Done の定義「コードブロックの桁が揃う」が未達**（`implementation-notes.md` Deviations に自己記録あり）。
   `src/main.rs` の `Font::with_name("Osaka-Mono")` は一度も解決されていない。原因は
   **PostScript 名をファミリ名として指定した不一致**（fontdb が照合するファミリ名は `"Osaka"`。
   ADR-0003 追記・ADR-0009 帰結で直接確認済み）。weight 完全一致の罠は Hiragino Mincho ProN 側の
   別件で、こちらの原因ではない。しかも `"Osaka"` に直しても、ファミリ内に比例・等幅の 2 face が
   同名・同 weight で並ぶため**名前の修正だけで等幅 face を選べる証拠がない**。
   `implementation-notes.md`「現在地」節の「Done 全項目満たしている」と**矛盾**している点は変わらず。
3. **リネーム欄の排他漏れ = 誤リネームのデータ整合性バグ**（初版時点は Deviations に記録のみ → **修正済み**）。
   リネーム欄を開いたまま `Cmd+N`・一覧クリック・`Cmd+P` で選択を動かすと入力欄が残り、
   そこで押した Enter が**新しい選択先を前のノートの名前でリネームする**。`selected` を動かす
   全経路の合流点（`open_note()`）で畳む形に修正し、3 経路それぞれ「古い名前で別ノートを
   リネームできない」回帰テストで固定した（修正を外すと 3 本とも落ちることを確認済み）。
   **実機での 3 経路の確認は実施済み（2026-08-11、使い捨て vault + release ビルド）**。
   `Cmd+N`: 新規ノートは日時名のまま（リネーム欄は畳まれ、Enter は本文への改行）。
   一覧クリック: リネーム欄が背景クリック扱いで取り消され、選択自体が動かない（クリック経路は構造的に到達不能）。
   `Cmd+P`: パレットを開いた瞬間にリネーム欄が畳まれ、Enter は選択ノートを開くだけ。
   3 経路とも標的ファイル（bravo.md 等）の名前・内容がバイト単位で不変であることを ls / cat で確認。
   なお初版指摘の「⌘ 混入修正が未コミット・ADR-0010 未執筆」は解消済み（53cb035〜dc7d694）。

## 問い 2: 人に使ってもらえる製品か — **条件付き**

ターゲットは実質「日本語で書く・macOS・git 管理の 1000 件級 Markdown vault・キーボード派の開発者」
（= 作者と同型）。この層への差別化は本物が 3 つ:

- **速度**（実測できているのは vault 読み込み 30.2ms = 約 1200 件と `view()` 構築 0.19ms = 約 1300 件。
  **GUI 起動全体は未計測**で、他アプリとの比較は同一 vault・同一端末で測るまで張れない）
- **日本語特化ファジー**（`fuzzy.rs` の全半角・かなカナ・半角カナ濁点合成の正規化）
- **mtime 規律**（無編集では 1 バイトも書かない = git・同期と共存できる）

判定を左右する欠落 3 つ:

1. **検索がタイトルのみ**（`refilter` は `note.title` しか見ない）。spec 非目標の言い分は
   「素の走査で足りる」だが、**素の走査による本文検索すら無い**（全 `raw` はメモリ上にあるのに）。
   非目標の理由付けと実装が食い違っている。他人が最初に詰まるのは確実にここ。
2. **外部変更と衝突する。** spec の前提「他ツールで同じファイルを触れる」に対し、`save_now` は
   自分が読んだ `raw` としか比較しないため、外部編集は打鍵→自動保存で黙って上書きされる。
   ADR-0007 で「本物だが不採用」と記録済みの意図的判断だが、前提と正面衝突している。
3. **導線がニッチ以外を全部落とす。** `VAULT` 環境変数のみ・vault 切替無し・cargo run 前提・
   macOS フォント前提。ターゲットを広げるなら全文検索より先にここが壁。

その他（implementation-notes「次の一歩」に自覚済み）: 新規ノートが日時ファイル名の羅列になる、
`.trash` をアプリから空にできない。

## 公開ラインに乗せる最短経路

1. README + LICENSE を書く（macOS 専用の明記を含む）
2. Osaka-Mono の決着。「選び直し」の一言では閉じない — `"Osaka"` に直しても等幅 face を
   選べる保証がないため、(a) 別ファミリ名の CJK 等幅を名指しする、(b) ライセンス確認済み
   フォントを同梱して fontdb に登録する、(c) fontdb/cosmic-text 側で face を直接選ぶ、の
   3 案を**等幅グリッド + 日本語実データの小さな spike** で比較し、採用案または Done の
   主張の変更を ADR で確定する
3. 誤リネーム修正の実機確認（リネーム欄を開いたまま `Cmd+N` / 一覧クリック / `Cmd+P` 選択の
   3 経路）と、起動性能を数字で語るなら GUI 起動全体の計測（cold/warm 区別・同一 vault）

その先は機能追加ではなく spec 側の判断: 「本文検索なし・外部変更検知なしをターゲット定義として
引き受ける」か「非目標を再決定する」か。
